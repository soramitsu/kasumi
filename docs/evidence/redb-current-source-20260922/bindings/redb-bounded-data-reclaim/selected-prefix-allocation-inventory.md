# Selected-prefix allocation inventory (separate frozen follow-up)

This follows the immutable f2103f19 reclaim patch. It does not qualify a total byte envelope or add a new native measurement. `followup-receipt.json` pins the exact unchanged vendor support files used below, the proposed files, and the test replacement manifest. No native/Cargo execution occurred.

## Exact prefix-owned state

Let K=16 encoded key bytes, V=3202 encoded PageList bytes, R<=400 selected records, J<=400 selected page IDs, H=MAX_BTREE_DEPTH=128, and P=the actual configured page size. The parser validates V and count 1..400 before removal. The extraction predicate is the zero-capture `|_, _| true`; the loop retains no caller callback, record vector or entry vector. A record failing its checked shape is not materialized into an owned PageList payload.

`ValidatedPageListPrefix` is one inline root/horizon/key/count shell. `DeferredReclaim` is exactly one inline `[PageNumber; 400]` plus `usize`; its native layout is not its 3200-byte encoding. It is a field of the actual WriteTransaction and is filled directly. Neither selected keys nor selected PageLists are collected. There is no local-to-deferred extension or second deferred backing. The later prepared allocator borrows this slice and the existing current-system Vec, using iterator.chain; it does not clone either list.

## Selection, extraction and the owners below them

* `SystemTable::range` → `BtreeCursorRange`: the all-range selection has unbounded encoded endpoints, so no endpoint payload. Only `next()` is used; the front cursor gets one ancestor Vec path, limited at descent to H. Back is never initialized. Each result creates a key/value AccessGuard pair over one shared page. The guards and PageList view drop each iteration. Page/cache/read-reference ownership is real and remains charged by the separately required database envelope; a 3202-byte record is not a claim that its enclosing physical page buffer costs 3202.
* `SystemTable::extract_from_if(..=last)` → `BtreeExtractIf` → `RangeMut`: lower bound is Unbounded; the upper bound owns one K-byte Vec. These wrappers themselves are inline and clone existing Arc owners; they do not box a closure. Only forward iteration is called. The back end remains Parked; one front cursor can be live. Resume/park/reseek keys are K-byte Vec copies and can coexist briefly; this is constant-count scratch, not one retained key per historical row.
* `CursorState.removed_indexes` is a Vec of indexes for the current leaf, in strict monotone order. At most R<=400 removals can be recorded by this extraction. `take_removals_ascending` moves its allocation rather than cloning it; a flush may retain that moved allocation while a replacement state is empty. Its existing growable Vec still has allocation capacity and reallocation peaks; the count bound is not an allocation-free promise.
* `record_removal_deferred` returns two Arc-backed AccessGuards for one leaf image. The loop reads and drops both before the next extraction call. `PageImpl::to_arc` and the page/cache machinery determine whether conversion shares a buffer or creates an image; no arbitrary collection of returned guards exists in this caller.
* `LeafRunRewrite` copies surviving pairs from affected leaves under one parent into `OwnedEntryBuffer`: `VecDeque<(Range<usize>, Range<usize>)>` plus `Vec<u8>`. `extend_from_leaf` additionally allocates a temporary Vec of retained pair ranges. Thus returned guards are zero-copy with respect to values, but removal scratch is not. Each run absorbs only leaves with removals, stops at the parent boundary, and may absorb one adjacent survivor leaf during merge. There cannot be more than R affected leaves plus that neighbor in one run. All copied survivors retain their actual key/value bytes; they are not limited to the selected rows' payload.
* `build_replacement_leaves` additionally collects `Vec<(&[u8], &[u8])>`, a Vec of packing ranges, and a Vec of replacement `(PageNumber, Vec<u8>)` separators. `replace_leaf_children` collects the replaced leaf page IDs. BranchBuilder owns child/checksum and key-reference Vecs; splitting can own separator keys. These collections coexist with the survivor buffer and old page references. They are required terms, not hidden inside DeferredReclaim.
* `CursorTree.freed` is a separate Vec of COW-obsolete system page IDs. Each cursor operation calls `drain_freed`: uncommitted pages are returned immediately through the original allocator path; committed pages move into the one `master_free_list`, which is this transaction's current-system Vec. Draining leaves the source capacity allocated. This scratch and the destination capacity can coexist. The prefix does not copy historical DATA page IDs into it; it records pages of the system Btree being rewritten.
* PageAllocator trackers, debug reference maps and cached page payloads may retain pages/backing after a cursor releases its immediate guards. Retained-terminal failure also retains the actual transaction. The candidate does not release their charge based on cursor loop completion.

## Useful geometry and the remaining bound obligation

For a canonical DATA leaf, the concrete RawLeafBuilder formula is `4 + n*(16 + 3202 + 4) = 4 + 3222*n` (fixed key, variable value offsets). For its fixed 16-byte-key branch, RawBranchBuilder requires `8 + 24*c + 16*(c-1) = 40*c - 8` bytes for c children. At P=4096, a one-page leaf holds one canonical record and a one-page branch fits at most 102 children. These are encoded-layout formulas, not a proof that every accepted tree page is exactly one P-byte allocation or a portable resident-byte charge.

A tight implementation estimator must still establish the largest canonical generated DATA leaf/branch allocations, cover accepted corrupt-page headers before their data reaches PageList::checked, derive each collection's actual requested capacity and pinned-stdlib old/new allocation peak, and include COW sibling/ancestor builder temporaries. The code supplies H and R bounds and parent-local coalescing, but it has no checked pre-admission API for all these collections. No fanout*P or R*V number is presented as a qualified total. Native type sizes and an allocator allowance remain necessary. The all-history vector formerly in process_freed_pages is removed; that alone does not meet the broader workspace goal.

## Other commit work which remains history-dependent

`flush_data_allocated_pages` still validates/extracts all eligible DATA_ALLOCATED rows up to its savepoint horizon. `pending_deleted_ids` produces the existing savepoint deletion collection. Savepoint restore has its separate suffix extraction. These operations can grow the current-system free Vec beyond the bounded DATA prefix's contribution. Also the allocator-state table is deleted/rebuilt per commit, and its full region snapshot copies/serialization scale with the admitted disk geometry. Current user freed/allocated page vectors are produced by the actual current transaction and serialized in 400-ID records; they are not bounded by this historical prefix.

Direct current-system exclusion therefore removes an obsolete durable queue and an extra list copy; it does not pretend that the current-system Vec has a finite per-profile bound already proven. A scratch profile without savepoints could forbid that capability through a mandatory profile, but no such unsupported fallback or new profile is introduced here. The source-hashed inventory makes these prerequisites explicit before any admission estimate or production batch adoption.
