# Canonical allocator payload and layout validation prerequisite

TARGET ONLY, on /Users/mtakemiya/dev/kasumi master. No actual source edits, Cargo invocation, compilation or native tests by this agent. The base is the root-integrated retained-opening and canonical-key packages. The manifest records exact source bytes and all static checks; runtime acceptance remains for the root-owned native gate.

The existing mandatory raw allocator-tree walk now invokes a record validator before any allocator decoder, typed traversal, stale-snapshot decision, repair callback, allocator reset, or begin_writable. There is no optional production validation mode. The cfg(test) raw-page unit helpers use the same raw walker with an empty record callback only to isolate raw key/geometry cases; all real database tests use the mandatory production callback. The existing infallible allocator deserializers and all serializers remain unchanged. No alternate format, conversion, legacy reader or writer is added.

The new page_store/allocator_snapshot.rs uses borrowed views, fixed arrays of scalar lengths (four bitmap levels) and at most 21 borrowed order views. Successful helper validation allocates no heap collection, decoded bitmap, encoded image or error string. Corruption maps to the existing StorageError::Corrupted. Nested lengths/end offsets, exact word counts, padded tree heights from immutable region capacity, per-order logical lengths, zero buddy-header padding, parent summary bits, producer-specific last-word tails, free-block nonoverlap, and maximal buddy merging are checked before the decoder can allocate from them.

The stream requires contiguous region indices from zero, full interior regions, one tracker followed by one exact-eight-byte transaction stamp, and a tracker covering every snapshot region within MAX_REGIONS. Every tracker order must have the same retained logical capacity and may optimistically name an existing full region, but cannot name a missing region. An absent/empty snapshot remains the supported repair trigger; an incomplete nonempty snapshot is corruption. Internally valid stale snapshots remain repairable.

Current canonical snapshots are saved before TransactionalMemory::commit's try_shrink. Unclean extension can also leave the physical file larger than its snapshot. Equality to the current layout would reject these canonical states. For a matching winning stamp, every snapshot page omitted by current layout must instead be proved free in the validated buddy representation; growth remains the existing resize_to path. Shrink and extension operate only after all records validate. Validation holds no state lock while reading tree pages; it snapshots immutable opening geometry and winner identity under the existing lock.

The raw walker also checks branch routing ranges. BranchAccessor::child_for_key routes equality to the left child, so children inherit a lower-exclusive and upper-inclusive key bound. Every nested separator and leaf key must fit those bounds. Separator equality to the current maximum of the left child is deliberately not required: removal may retain an older valid separator. The existing branch test now includes a canonical separator with incorrect routing that previously passed global leaf ordering.

Prepared tests: six new borrowed-view/producer/layout tests and one new native test containing 16 malformed canonical payload fixtures (clean/unclean), plus strengthened original branch coverage. Actual producers are exercised across orders 0..20; partial and full lengths; allocate/free, shrink and re-extension; exact-byte decoder roundtrips and checksum equality; retained tracker capacity after 1001 -> 1 -> 2 regions and the maximum region count. Actual allocation instrumentation checks valid helper paths allocate zero. Malformed nested offsets, truncation, order/height/length fields, summary bits, overlapping free blocks, unused free markers, incomplete and noncontiguous records, and unsafe winning contraction are refused. The native test exercises consuming, read-only and retained opening entry points, proves repair callbacks stay at zero, and compares complete file bytes. These tests are prepared, not executed here.

Remaining limits: this does not establish that allocator ownership agrees with every reachable user/system root or pending DATA page; checksums remain the existing separate mechanism. It does not establish absence of pessimistic tracker markers for existing free regions. It does not canonicalize the PageNumber representation or validate unrelated tables. Cache payloads, ancestor page guards, recursion/native stack, decoder allocations, full prepared allocator copy, checksum scratch, protected maintenance page pool/extension and total process RSS/workspace are not qualified. Structural/semantic helper work is finite per actual payload but no whole-database scan or time budget is claimed. Broader original fault and performance gates remain required.
