# Independent PageList prerequisite review

Verdict: no remaining static blocker for this narrow prerequisite WHEN the required private-key Copy follow-up is applied with it. The original frozen patch alone contains use-after-move compile errors. No Rust compiler, Cargo, native test or production source edit was used for this review.

## Required correction

TransactionIdWithPagination originally derives only Debug. validate_page_lists(lower..) moves lower before the subsequent extract_from_if(lower..); the allocated-page purge repeats the same issue with ..key. The new regressions also reuse moved first/second keys and key..=key. The independently checked follow-up changes exactly that private two-u64 key to derive Clone, Copy, Debug. Its saved base exactly matches the main proposal and no other bytes change. This resolves the concrete move problem without a new record format or compatibility path.

## Validated scope

All three producer shapes were traced: store_data_freed_pages_for and write_allocated_pages_entry reserve400 entries (3,202 bytes), and store_system_freed_pages reserves200 entries (1,602 bytes). Each producer inserts only with a nonempty source and drains at least one element; a successfully produced record therefore has a nonzero count. PageList::checked first checks the exact byte length before reading u16, then rejects0 and counts beyond the selected canonical capacity. CheckedPageList::get bounds the caller index; each checked buffer is large enough for every accepted indexed entry. All existing read/debug/recovery/savepoint entry consumers switch to checked views with the corresponding family. Unused padding remains unconstrained because current in-place writers initialize length and used values, not a canonical zero padding. There is no shorter or alternate format decoder.

process_freed_pages keeps its existing system-namespace mutex while it validates the eligible DATA and SYSTEM ranges, stores two inline tokens, then extracts either range. An invalid later DATA record or invalid SYSTEM record therefore rejects before any selected record removal. The token carries exact table definition, kind, free_until and Option<BtreeHeader>. Before extraction, get_system_table_root compares that header; its TableTreeMut getter includes staged pending root updates, so this is the actual current table root rather than only the older master-tree header. The exclusive namespace lock prevents a concurrent table mutation between checks. Opening a table may stage unchanged metadata and mark the transaction dirty, but it does not remove eligible records. Failure poisons the transaction; the test explicitly aborts the actual transaction and checks namespace restoration rather than treating poisoning as rollback.

The extraction helper explicitly invokes close and returns an otherwise-successful scan's original close error by move. A prior iterator error remains the primary result instead of being replaced by the repeated PreviousIo that follows an iterator-latched error. Either resulting error poisons the transaction, preventing publication. The allocated-record purge also validates before removal and explicitly closes; savepoint purge retains its prior poison-on-error closure and adds shape validation. An error during durable commit additionally remains under the existing allocator-state fence. Header publication, allocator-copy preparation, deferred freeing and growth settlement are not changed by this patch.

The real close-failure fixture uses a valid SYSTEM pending-page tree whose eight records name actual allocated pages. It commits that seed, disposes the settled transaction with a matching live database, exhausts the actual current free-page count, extracts one entry and then injects a failure only after a real backend sync. RangeMut holds the removed-index batch until close finalizes the COW path, so the intended injected boundary is actual extraction finalization. The fixture asserts actual file growth/sync, exact original error marker identity, poisoned transaction, failed owner, retained abort result, refused settled disposal and database WaitingForTransactions. It retains the full original error, exact uncertain transaction, actual retained database and file in one fixed test slot. It does not drop an uncertain owner as purported cleanup evidence. This is source-reviewed test intent, not a claimed executed pass.

## Explicit limitations retained

This remains an all-history traversal and two coexisting deferred page collections; no bounded-prefix policy, admitted reclaim-memory bound, physical maintenance headroom or net progress proof is delivered. Shape/count validation does not validate encoded PageNumber semantics, duplicates, overlap or allocator reachability. The close helper is not a two-outcome aggregate: with an existing primary Err it drops its close return, and generic BtreeExtractIf::latch_error already discards a secondary close error. Existing RangeMut close also uses first-error precedence. The package must not be cited as full custody of all independent close/panic phases. Its directly observed first-close failure path is the one tested here. These outstanding dependencies are already explicit in the package README and remain necessary before full production adoption.

Static hashes of all four proposed files and their current bases matched the manifest; the required Copy follow-up stacked exactly. git apply --check passed for the main patch against current source. Strict lint, compilation and the actual-file tests remain parent-owned gates.
