# Current redb source checkpoint proposal

This is a proposed current-source checkpoint for the Kasumi first release on master, not release acceptance. The original redb canonical import evidence remains unchanged. This successor uses the existing redb-provenance verification contract without changing the checker or introducing a format fallback.

`provenance.json` preserves the original published crate and companion archive identities, original published/companion file hashes, and prior canonical fork hashes. It records all 109 current regular files with exact SHA-256, byte counts and modes. Two original removals remain explicit null-fork entries, giving 111 provenance rows. `source-inventory.json` is the complete current inventory; `changes-since-import.json` identifies the 25 changed original entries and 12 later additions.

`evidence-bindings.json` links exact preserved patch, scoped review and root application records, plus completed component gate inputs, outputs and receipts. Copies under `bindings/` are byte-identical to their identified repository inputs. Historical review receipts qualify their own proposals, not every later file revision. Earlier run 157–161 results are retained with exact lists of current files that differ from their recorded source, so those results cannot be mistaken for current-source qualification.

Current source matches the recorded Rust and Cargo inputs for run 162 (211 vendor unit tests), run 163 (strict vendor all-target/all-feature Clippy) and run 164 (296 tests across all ten public integration targets). All three original receipts report exit 0, unchanged inventoried source and drained process groups. Their inventory scope excludes documentation, so the final CHANGELOG/KASUMI_PATCH wording is identified separately as a checkpoint review input. These records are component results only.

The archived packages 102, 143, 145, 146 and 154, applicable manifests, the scoped 143 review and corresponding root application receipts now bind historical changes to checked_backend_tests.rs, canonical_format.rs and integration_tests.rs, together with their other affected paths. This is partial historical coverage, not proof of a complete patch chain or blanket current-source review. All current Rust/test files match runs 162–164. CHANGELOG.md and KASUMI_PATCH.md have no source-patch history binding and require explicit root review of their current disposition text. Every current byte is inventoried.

The allocator validators and retained owner primitives do not complete the production storage census, original-owner adoption at every caller, exact maintenance page/extension reserve, complete reachable-root ownership correspondence or total process/workspace memory bound. Upstream container, audit and fuzz workflows remain unpassed. No runtime input is made backward compatible by this metadata. Removed compatibility tests remain removed; their original hashes are provenance only.

The parent must review this concrete checkpoint before deliberately changing vendor/patch-manifest.json. An adoption receipt may reference these exact proposed bytes; historical evidence, including the proposal status here, should remain immutable. The separate candidate support update changes only vendor/README.md's recorded hash/size to its final current text. Other five inventory roots and the other three support entries remain exact.
