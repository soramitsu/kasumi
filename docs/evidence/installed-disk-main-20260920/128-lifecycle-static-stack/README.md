# Run128 focused static lifecycle stack comparison

The exact Mach-O ARM64 lifecycle binary is SHA256 `631110f244e868c72e9966ec5af1df0d484b63bb8c26ffcde3d8c00a730ec098`. Before and after hashes match for that binary, all three relevant source files, terminal run128 receipt and the prior run123 manifest. Current source matches the applied frozen vote probe and current-leader observation proposals. This is static analysis with llvm-nm and selected-range llvm-objdump only: no Cargo, binary/test execution, debugger, source edit, stack setting or deadline change.

The actual separated phase call edges remain intact. Outer orchestration calls preparation through its 64-byte Box::poll adapter, then independently calls expiry, continuation and publication adapters. Exact sites and targets are in selected-call-edges.json. Preparation and continuation have no selected direct or adapter call to expiry/publication; source still returns the actual CompletionFixture before expiry starts, preserving live fixture, request, signed completion and attestations. The earlier giant combined frame has not returned.

Each adapter remains 64 bytes. The named outer+adapter+phase sums are preparation 739,440; continuation 791,424; expiry 422,464; publication 500,576 bytes. These are selected simultaneously active frames, not whole-thread stack bounds. Runtime wrappers, nested service/storage futures, generic helpers, copy routines, panic/destructor paths and other callees add frames. Run128 includes both the new probe and the independent current-leader observation correction; the per-frame deltas cannot all be attributed solely to probe instrumentation. The run123 artifact did not preserve Fixture::open/configured prologues, so no old/new delta is claimed for those functions.

Fixture::new, limits, configured and open polls measure 21,200, 20,944, 71,264 and 28,912 bytes respectively. The probe is constructed during configured, before open is polled. The binary has consecutive configured calls to BootstrapVoteProbe::new at 0x100039858 and Arc::new at 0x100039868; those callee frames are not simultaneous. The new probe constructor is 35,664 bytes. Its actual inline slot construction calls from_fn (11,840) -> try_from_fn (35,408) -> try_from_fn_erased (3,232). These four selected frames total 86,144 bytes. The binary explicitly copies 0x2e00 (11,776) bytes for 32 slots, with per-slot stride 0x170 (368). The erased constructor uses a loop, not a 32-deep recursive call. Debug compilation has several real array-sized copies; the construction cost is not zero. Arc::new separately measures 12,064 bytes. This constructor-chain observation is not a total construction peak: its parents and other helpers add stack.

The ordinary probe send constructor is 672 bytes and its async poll is 2,864 bytes. begin is 1,520; candidate is 464; history is 64; finish is 352; Guard::drop is 192 bytes. The actual send poll calls begin, forwards to the original router and polls its original boxed future, then calls finish or drops its guard. It does not call probe construction or rebuild the slot array. Guard::drop calls finish on cancellation/unwind; none of the measured send/begin/finish paths introduce a direct recursive call to themselves. The fixed history storage therefore contributes an observed one-time construction stack path plus bounded per-RPC observation work, while the original router/storage execution remains separate work with its own frames.

The selected measurements show the intended phase separation is preserved and quantify the fixture instrumentation overhead. They do not prove that every thread path is safe from stack exhaustion, identify the missing run117 crash instruction, establish election timing, or constitute a test pass. There is no new static blocker identified for the root-owned original runtime gate with its unchanged stack and workload. That runtime gate remains necessary.

All static command argv, exit statuses, timing and output paths are in command-receipts.json. The first local Python symbol-indexing attempt was interrupted before disassembly because it used a quadratic in-memory lookup; its interruption is preserved in static-parser-interruption.json. The corrected lookup used sorted unique addresses. This interruption did not execute or signal the lifecycle binary. Full selected function disassembly and prologues preserve the arithmetic, including stack-probe loops counted by their target allocation rather than only one loop iteration.
