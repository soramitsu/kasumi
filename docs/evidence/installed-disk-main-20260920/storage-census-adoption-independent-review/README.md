## Blocking finding: relinquishment authorizes future errors

**P1**, `proposed/crates/kasumi-store/src/storage_opening.rs:254–259` and `443–448`, consumed by the drive decisions at lines 122–123 and 396–397.

Both facade `retire` methods permanently set the shared `outcomes_released` flag before driving or synchronizing with the actual owner state. Opening retirement can enter the first physical close only after setting the flag. If shutdown now returns an error and backend close succeeds, retained redb correctly reports physical closure while keeping its original shutdown error. `DatabaseOwner::drive` nevertheless returns true through the already-set flag. After the final facade is gone, the census destroys the actual owner, its newly generated error, and then its charge. No caller ever had the chance to inspect or relinquish that new close observation. This directly violates the candidate's claim that positive physical close does not erase an unacknowledged failure.

Concrete interleaving: prepare/open successfully; optionally recover another facade to the same owner; call `retire` before any close observation; let the close's sync or growth settlement return a new error while backend release returns Ok; drop any remaining facade and drain. The current code can retire the original error and owner. This is an actual retained-redb settlement, explicitly exercised by `vendor/redb-4.2.0/src/retained_database_tests.rs::original_shutdown_error_survives_successful_backend_release`, and not a hypothetical impossible return combination.

The queued writer has the same lifetime error. A recovered facade can set the flag while another facade is about to execute the request or holds its active state. The latter can subsequently produce a new body/terminal/disposal observation already authorized for destruction. Strong Arc counts postpone destruction while a facade exists; they do not revoke the stale authorization when that facade is dropped.

Required successor: bind explicit relinquishment to an already terminal, observed report/attempt state under the actual owner's serialization. It must not cover future close, abort or disposal observations. Beginning a new terminal phase must invalidate any earlier authorization. A queued request must be sealed/cancelled before its terminal report can be relinquished; a busy active worker cannot be acknowledged or force a blocking drain. Preserve original objects and errors until their own report is explicitly relinquished, and preserve physical uncertainty even after relinquishment.

Required tests: (1) a new shutdown error plus successful backend close produced after an initial retire must keep the exact original error pointer and charge after all initial facades disappear; recovery must observe that same original before final relinquishment can retire it; (2) two facades to queued work must not permit one facade to authorize later body/terminal errors from the other; (3) acknowledgement attempted while a real worker is active must not wait for it or authorize a later observation; (4) new abort/disposal entry after an earlier observation must not inherit release permission. Keep existing uncertain commit/abort retention tests and successful backing-before-credit assertions.

## Reviewed properties without another blocker found

- The fixed census owns the actual erased Arc independently from each facade and stores its own resident lease. Private facade reconstruction clones the existing owner and exact provider, with generation validation and no exposed Weak/raw owner Arc. Cancellation alone cannot remove the slot or destroy the actual accepted request.
- Drain metadata access uses `try_lock`. `servicing` and the fixed pending scalar gate each effectful stage. Post-effect contention preserves the actual installed owner or stage result. Other drainers cannot dispose or reuse a slot before the prior stage publishes completion; generation checks reject stale identities. The original panic payload has a separate OnceLock-backed mutex, so holding its observation does not hold census metadata.
- Drive panic keeps the original installed owner and original payload. Uniqueness is checked under metadata serialization before removing the actual Arc; `try_unwrap` remains the positive retirement operation. Payload disposal occurs outside metadata locks; lease retirement follows only after payload disposal returns. The cell becomes vacant only after the actual lease Box/token retirement returns. Destructor panic is conservatively retained without replay and does not falsely claim intact partially destructed payloads. Unexpected sharing and lease-retirement panic preserve a retained state and fence registration.
- MemoryCore includes the checked fixed slot-array charge in its initial bookkeeping check before allocation. Its own Arc and embedded census share the exact provider data address; binding happens before publication and does not create a Weak that would defeat sampler initialization. TestDiskMemory follows the same base-before-allocation order. These are exact listed backing charges, not the complete storage/workspace census.
- Concrete opening installs the prepared NodeFile and vendor retained owner before file acquisition and places an acquired NodeDiskFile in the existing owner before envelope checks. This wrapper does not repair ownership loss inside an underlying acquisition function; managed acquisition remains a separate dependency.
- The closed NodeTables request is registered before its serial execution wait. The real retained transaction is installed before the body. Body failure takes abort, success takes commit, and vendor settlement/disposal preserves actual outcome identity. Close seals new work, and busy request/database state returns retained through nonblocking access. Census metadata progress is nonblocking; synchronous filesystem operations and the provider's existing retirement mutex are not a proof of global wait-free or bounded-latency drain.
