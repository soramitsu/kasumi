# Retained census steps and explicit namespace capacity

This target-only successor replaces the overloaded `max_census_entries` contract. `max_persistent_files` (F) counts retained regular files; `max_persistent_subdirectories` (D) counts retained directories below configured roots; `census_work_per_step` limits native `readdir` calls in one synchronous advance. Configured roots (R) are separate. Every generated production and fixture value preserves its original N for all three fields. Old and mixed old/new serialized configurations are rejected; missing new fields have no default.

Both already-retained inode banks fund F+D+R entries, preserving default F=D=1,000,000 and 4096 file/directory handles. The inactive bank now admits the whole permitted namespace during recensus. Neither dots, EOF nor a step boundary consumes an inode slot. No third map, post-publication capacity expansion, allowance increase or smaller file quota is introduced.

For a permitted finite tree, native calls comprise F+D child entries, 2(D+R) dot entries, and D+R EOF observations: F+4D+3R. Checked arithmetic rejects an unrepresentable bound. Each advance performs at most `census_work_per_step` calls; an invalid changing/repeating stream must stop within the checked whole-job bound. Configured depth and name bounds remain required. Files and subdirectories each have a separate logical census check before insertion. Roots do not spend the subdirectory budget.

`CensusSession` retains the same inactive bank, root iterator, root identity, preallocated DFS stack, actual independent native directory streams, accumulated counts and original failure between advances. The current synchronous `open`/`reconcile` driver retains its existing registry/State guard through every Pending step and yields the current thread between steps. It checks cancellation without restarting enumeration. No public scheduler/session API, asynchronous cancellation responsiveness, changed deadline, or kernel I/O latency bound is claimed.

The session closes streams explicitly on EOF and on every returned error; its destructor covers unwind. Each successful `fdopendir` registers its slot before any fallible handoff. Exactly one `closedir` consumes the pointer. A success retires the native resource before returning the slot; a failed close preserves the slot and first original errno and never retries a possibly consumed pointer. A primary read/cancellation error and an independent close error both survive the synchronous result. Failed/incomplete/unwound scans reset only candidate entries; the preallocated backing and published ledger remain retained.

Reconciliation stores native census custody within State. An uncertain close retains the installed owner and reservations, seals device admission, and blocks subsequent pause/reconcile drain success. Snapshot fields expose outstanding census streams and the first native close errno. Existing live file, directory and operational cursor checks remain required.

Initial census precedes publication of NodeDisk and its device registration. `PreparedCensus` therefore owns a resource bundle containing actual roots, ancestor locks, both inode/live banks and their already-admitted owner/registry leases. On an ordinary fully closed failure it destroys backing/descriptors before retiring the leases. If error or unwind leaves an uncertain stream, it retains that existing bundle's heap/descriptor owners until process exit without allocating another retention wrapper. The retained root locks prevent another constructor from adopting that root. This intentionally does not poison a shared device on an ordinary unpublished census failure.

An operational enrolled directory cursor has one retained directory's exact child count, so its whole returned-entry bound is `children + 2` for dots. It no longer mistakes the census step budget for its own lifetime quota; generation, identity, name, extent and explicit-close checks remain unchanged.

The original tiny-N native failure remains immutable at `../namespace-census-contract-gap/native-baseline-01`: seven accepted managed files under N=8 failed recensus when dot entries exhausted the old whole-job quota. The successor tests require successful recensus for both seven and all eight admitted files, and a full F=8/D=8 namespace across multiple eight-call steps. Other tests cover actual retained stream descriptors, independent file/directory excess, cancellation, incomplete finish, unwind, old-ledger/promise preservation, uncertain close custody, and actual FD retirement before lease credit.

This package is not release-ready directory adoption. Production managed mkdir/rmdir and remaining raw listing migrations are separate unfinished work. Explicit directory policy ceilings still do not prove a supported filesystem's pre-effect physical allocation bound. The fixed-map requested-byte proof does not establish allocator/native buffer bounds, whole-server RSS plus reserved high-water fit, or a usable 2 GiB configuration. The current native test suite and integrated server serde tests have not yet run against this successor; root owns the execution window.
