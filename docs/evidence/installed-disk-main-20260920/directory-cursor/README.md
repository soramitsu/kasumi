The new consuming `NodeDiskDirectory::cursor` accepts only exclusive, enrolled directory custody. It opens an independent native stream at the retained descriptor, checks its actual inode and ancestors, and keeps the counted directory owner through stream retirement. Returned names borrow the stream and cannot survive another read or Drop. The API exposes names and file/directory kinds, with no raw descriptors, writes, or implicit adoption.

Each native entry consumes the existing traversal-work allowance, including dot entries; non-dot entries must match the census/settled child count, strict byte-name limit, inode ledger, private ownership and retained parent binding. Files use the existing settled/unsettled enrollment predicate: device, type, link count, exact known logical length, reserved length, full extent allowance, and exact durable bytes/pending for settled enrollment. Directory ancestors are verified before and after the observation. A checked global namespace generation advances with managed file namespace settlement, so a rename that preserves directory size, blocks and child count invalidates a reader. Such managed invalidation returns sticky `WouldBlock` without fencing healthy storage. Cancellation is sticky `Interrupted`, retires the stream, and retains directory custody until the cursor drops. A failed read cannot masquerade as later EOF. Identity/ownership/I/O uncertainty fences admission.

Actual `closedir` runs before stream-slot credit; directory resources retire afterward through their existing owner. A close error never retries a possibly consumed DIR. It retains the stream count and an explicit strong installed-owner reference until process exit. The existing installed registry already holds each NodeDisk strongly; the extra reference is conservative, and the test proves actual retained memory custody rather than claiming the registry used weak ownership. Success, error and cancellation close outside the state lock. There are no production callbacks while that lock is held. The test-only close pause occurs after the libc call and before credit, allowing another thread to inspect the actual stream and directory descriptors.

Operational streams are capped by the existing `max_depth` census-stream capacity. Every stream also retains an independently counted directory owner. All pause/reconcile/fixture-refresh guards include the stream count, so census and operational stream workspaces do not overlap. An explicit checked size comparison makes the operational Rust cursor fit the existing census-object allowance. Independent file and directory owner limits remain unchanged; no million-entry, 4096-handle or 2 GiB policy was reduced or raised. This is a lifetime/capacity argument conditional on the existing workspace bounds; it does not qualify their numerical estimates.

The read-only backup cleanup listing now obtains a counted cursor for its existing object directory. It explicitly closes on every normal Result path before returning; a partial page cannot conceal close failure, and simultaneous listing/close failures retain the primary anyhow error and original close io::Error through context. Authentication checks, canonical object names, bounded `limit + 1` selector storage, and page shape remain. `Directory::child` still uses raw mkdir/openat, and other raw mkdir/rmdir callers remain. A previously unenrolled directory is rejected; there is no fallback. Consequently this caller migration cannot be deployed until managed namespace creation/removal is completed. It is included as a concrete API migration for review, not as a claim of complete production adoption.

The inherited memory formula still uses `4 * count * (size + 16)` table estimates. These are not strict bounds: tombstone churn may enlarge retained backing beyond current live cardinality, and old/new backing can overlap during rehash. The prior approximately 1.92 GB owner estimate leaves about 227 MB before the actual engine/cache/other owners and does not prove the default server usable. The actual admission rule requires both all reservations within max_bytes and sampled RSS plus all reservations strictly below the high-water threshold. A subsequent fixed-preallocation/no-growth ledger implementation needs explicit retained `2N + R`, replacement `N + R`, and swap/retirement backing geometry using the pinned Rust/hashbrown layout; lowering an estimate coefficient is insufficient.
