# Admitted namespace versus complete census: unresolved contract

This is a static design record, not a policy change or passing release result. Only target files were written on master. Native work is held for root lifecycle129.

The cumulative directory proposal permits up to N files after a census that may have retained up to N+R directories. Its retained ledger bound is therefore2N+R. File create checks files<N. Its census independently increments `work` for every native readdir entry, including '.' and '..', and fails when work>N. It also currently limits candidate logical inode entries to N+R. These are incompatible once runtime admission expands the namespace.

A flat counterexample needs no directory growth: N=8, one initially empty enrolled root, seven managed files created/settled/closed successfully, then pause/reconcile. On the supported native stream with '.' and '..', the same namespace consumes nine returned entries and census rejects it. At the full eight-file quota it needs ten. The next native diagnostic must retain that rejection as evidence of the old cause, not encode failed reopening as desired behavior. Directory-heavy retained namespaces strengthen the discrepancy: old directory admission plus newly admitted files can exceed both the work bound and candidate N+R cardinality.

No algorithm can completely enumerate N distinct files plus dot entries within a strict total quota of N returned entries. Batching alone does not fix that contradiction if the field remains a total-work quota. The first release must explicitly separate namespace cardinality from traversal work, rather than lower file capacity or silently reinterpret the existing field.

Proposed coherent first-release semantics, for parent review before implementation:

1. Keep independent logical cardinalities: files<=N and directories<=N+R (including the R configured roots). All managed mkdir/create paths check their corresponding cardinality before namespace effects; directories never consume file slots. The live and candidate inode unions may each reach2N+R. Both fixed-map physical banks already have that capacity, so correcting candidate cardinality requires no additional map allocation or policy-byte increase.
2. Retain the current numerical traversal allowance N as an explicit **work-per-step** bound, named separately from logical cardinality. A step counts native readdir calls including EOF, with cancellation and strict identity checks. It yields an incomplete cursor/session instead of treating budget exhaustion as a corrupt namespace or publishing partial accounting. The old API that conflates completion and one work quantum should be directly migrated, without a compatibility default or automatic adoption path.
3. Bound the complete job structurally as well. For F files and D directories, ordinary stable enumeration returns at most F+(D-R)+2D entries and makes at most F+4D-R readdir calls including EOF. At F<=N,D<=N+R, that is at most5N+3R calls. Use checked arithmetic and explicit supported-filesystem enumeration assumptions; a duplicate/extra-entry anomaly or exhausted structural bound fails closed. This is a declared complete-job bound derived from admitted namespace size, not a hidden increase of the per-step budget. Metadata/stat/fsync/path checks require their own declared work units if the policy intends to count more than readdir calls.
4. A resumable session exclusively owns the inactive bank, bounded traversal stack, exact retained directory descriptors, root/ancestor custody and cancellation state. The current active ledger/counters/promises remain unchanged while incomplete. Managed operations stay paused; no file/directory/cursor may overlap a reconciliation session. Each step resumes the same actual stream state; it does not restart from a path or reread already processed work without counting it. Success requires complete traversal, final identities/syncs, cancellation checks and accepted device promises before swapping banks and reopening admission.
5. Dropping/failing a session closes actual stream/FD ownership, retires the candidate entries and returns the already-funded inactive bank before any session/drain credit. A partial census is never registered as complete. If the native close outcome is uncertain, retain the corresponding custody and fence exactly as the enrolled cursor does. The session must not place a !Send DIR pointer into a formerly Send NodeDisk without a sound ownership design; a pinned worker/session or an owned detached inactive-bank capability needs explicit caller integration and cancellation/drop tests.

This choice requires a direct configuration/API migration: separate file and directory cardinalities from work-per-step (and document/validate the structural total). If N must instead remain a strict total-readdir-entry policy, complete reopening at the original file quota is mathematically impossible. That conflict must remain a release blocker, not be hidden by retry loops, deadline increases or weakened tests.

Planned native evidence after the hold: old tiny-N flat failure with exact consumed source/binary/argv/drain; directory-heavy old failure; corrected multiple-step completion with each step<=the unchanged numerical work quantum; exact original logical file/directory capacity after completion; cancellation after partial and full candidate; no partial publication; no per-step allocation/backing growth; final actual FD/candidate retirement. Full supported-filesystem physical directory growth and whole-server RSS/reservation fit remain separate open qualifications.
