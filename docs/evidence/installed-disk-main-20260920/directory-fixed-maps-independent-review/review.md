## Candidate and prior hazards

The candidate-source-sha256.json file identifies nine reviewed files layered on the immutable directory-cursor cumulative proposal. node_disk/file.rs is byte-identical to that prior layer. The review checked the new fixed_map module and tests, every live/accounted mutation in file preparation/publication/reclaim/retirement and census, namespace existing-entry updates, constructor/registry charge order, reconciliation and memory formulas.

Three hazards are closed structurally: pinned HashMap::insert reserves even for an occupied key, so replacements use get_mut plus mem::replace; empty HashMap::clear can retain tombstones, so reset drops drain even at len zero; a partial cloned spare could retain hidden Weak backing after file-slot retirement, so ResetCandidate drains it on return/error/unwind before State unlock. ## Capacity and custody proof

Map::new performs the only try_reserve allocation and requires actual capacity >= logical limit. All subsequent reservations are checked certificates, never allocator calls. Absent insertion checks len < logical limit and len < actual capacity again immediately before HashMap::insert. Existing-key replacement never reaches that insert path. Under pinned Rust 1.97.1/hashbrown 0.17.1, capacity-len is growth_left and reserve(1) cannot grow with positive growth_left. Exact pinned source inputs and line-level proof are preserved separately in node-disk-fixed-bank-proof.

Both inode banks have retained physical/logical capacity 2N+R outside a census. A staged census uses one existing spare at logical N+R and returns scalar Totals; there is no third HashMap or allocating HashMap clone. Completion restores the larger retained limit. Live owners use two H-capacity banks. Rebuild copy-before-swap preserves the active map on Clone failure; the reset guard drains all partial or old values before its mutable call returns or unwinds. Empty-bank drain restores controls and growth without replacing its backing. No raw mutable HashMap escapes.

prepare_file holds the actual State mutex from both capacity certificates through PreparedFile construction and execute/drop. Neither parent preparation/settlement nor verification consumes a new inode/live-map slot in that interval. O_CREAT is followed by at most one accounted and one live insertion. Ordinary extent updates and post-rename binding/Weak replacement use existing-entry mutation. Reclaim removes entries only after its physical completion protocol. Thus no other thread can spend the prepared certificate before publication. PreparedFile field ordering retains serialization through temporary metadata retirement.

A concurrent final file owner may close its resources while a live-bank rebuild holds State, but cannot retire its registration until that guard unlocks. Successful and interrupted rebuilds drain duplicated Weaks first. FileOwner::retire_registration then removes the exact original registration and drops its final Weak before publishing open_files credit. Publication's existing Weak replacement likewise drops old backing under State while retaining the prepared new owner. Census staging is only used for Copy inode values, never for the live Weak bank.

Reconciliation requires actual file/directory/cursor drain under State and root custody, scans only the spare, and cancels that spare on ordinary scan, cancellation, arithmetic and shared-promise failures. Old authoritative entries and counters remain unchanged on those errors. After complete scan and cancellation checks, shared promises are accepted before swapping maps and scalar counters; no fallible allocation or arbitrary destructor follows that publication. A census panic leaves active enrollment intact and State poisoned; it may retain a charged partial inode candidate until owner destruction, but cannot hide a live Weak reference or release its funding. Fixed table allocations drop with State before the NodeDisk resident lease; constructor failures likewise free local bank backing before the outer charge.
