# Run123 static lifecycle stack comparison

This analysis reads the exact newly compiled Mach-O ARM64 binary with llvm-nm and llvm-objdump. It does not execute that binary, launch a debugger, invoke Cargo, edit actual source, or adjust stack/timing settings. The branch is master in /Users/mtakemiya/dev/kasumi. Binary SHA256 is c8e9e7dc2ac7b878f9462a4b683469119fa78154682f8c131f6065f17f2cf85f. Before/after hashes cover that binary, tests/lifecycle.rs and tests/common/recovery_control.rs. The latter exactly matches the reviewed phase handoff proposal (6e6e9477...).

The new measured frames are preparation 623,632 bytes, activation/retirement continuation 681,136 bytes, outer orchestration 109,760 bytes, expired-completion resolution 312,256 bytes, and route publication 390,336 bytes. Each selected Box::poll adapter uses 64 bytes. Full prologues and exact arithmetic are preserved separately.

The outer poll now calls each phase through its own Box::poll adapter. The preserved call edges show preparation at outer call 0x10014dd38 -> adapter0x1000d2ba4 -> preparation0x1001308dc; expiry at 0x10014e140 -> adapter0x1000d2c34 -> expiry0x100146cf4; continuation at 0x10014e440 -> adapter0x1000d2b58 -> continuation0x10011ef80; route publication at 0x10014e6ac -> adapter0x1000d2bf0 -> publication0x10013fe00. Neither preparation nor continuation has a direct or Box adapter call to expiry or route publication. The source explicitly returns preparation's exact live fixture and original completion before entering expiry, then enters continuation only after expiry returns. Thus the old preparation/continuation frame no longer remains on the stack during expiry resolution.

Run117's three named outer + complete_recovery + expiry frames totaled 1,732,976 bytes, excluding adapters and other callers. Run123's corresponding outer + expiry frames total 422,016 bytes (422,080 including the 64-byte adapter): 1,310,960 fewer bytes in the named frames. The other measured phase compositions, including outer and one adapter, are preparation 733,456, continuation 790,960, and publication 500,160 bytes. These are phase-composition measurements only, not bounds for the entire active thread stack: runtime/test wrappers, helper futures, service/storage calls and destructors add their own frames. The root test poll adds 11,008 bytes; it is not included in those phase totals.

The expiry frame is unchanged at 312,256 bytes. Ordinary helper frames remain prepare_next 33,568; resolve_phase 24,128; commit_next_control 18,416; commit_next_control_for 68,752; snapshot 2,944. The existing leader poll and diagnostic remain 8,208 and 368 bytes respectively. This isolates the intended improvement to real phase composition; it does not attribute the missing run117 crash trace to a specific instruction or to the diagnostic.

The binary demonstrates the intended stack-pressure reduction and supports one coordinated successor test of the original fixture. It is not a runtime test pass or proof that no other stack-intensive path exists. Run117 had no crash backtrace, and run120's same-binary debugger pass did not recover one.
