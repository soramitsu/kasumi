# Static stack evidence for lifecycle run117

The exact binary SHA is 5b01407141bac88d2db20ed91ae5396525f0983b11bd58c0c7d898cbf55615ad. This artifact was produced with llvm-nm and llvm-objdump only. No Cargo invocation, test execution, debugger launch, or actual source edit occurred during this investigation.

Run117 exited with a native stack-overflow SIGABRT on the named libtest thread after 5.04 seconds of compile and roughly 55 seconds of execution. It supplied no crash backtrace. Root's separate run120 launched the exact binary under LLDB and the test passed in 101.81 seconds; it therefore supplied no faulting stack. These facts do not identify one exact faulting source instruction or establish that the new leader diagnostic was executed.

The exact ARM64 prologues establish unusually large always-present debug poll frames. complete_recovery::poll at 0x10011e750 probes 0x149000 bytes, subtracts 0x5e0 more, and has a 0x20 saved-register frame: 1,349,120 bytes. resolve_expired_completion::poll at 0x100147554 similarly requires 312,256 bytes. exercise_completed_recovery::poll requires 71,600 bytes. The direct call at 0x10012c374 enters resolve_expired_completion::poll from complete_recovery::poll, so those three frames alone occupy 1,732,976 bytes before the test/runtime wrappers, timeout/phase helpers, service calls, serialization, snapshot validation, or storage stack. For example, the expiry helper itself calls commit_next_control::poll and resolve_phase::poll. This is concrete stack pressure, not a measurement of the complete maximum stack or a claimed reconstruction of the missing crash trace.

The existing route-publication split correctly keeps its 390,336-byte poll frame outside complete_recovery's poll frame. Box::pin heap-allocates future state but does not remove the currently executing poll frame. The expiry-resolution helper is still nested inside the 1.35 MB poll frame. A real phase handoff can remove that composition: return the actual fixture/request/keys/completion first, poll expiry resolution after that future returned, and only then poll the activation/retirement continuation.

Comparing current lifecycle.rs with the saved113 diagnostic base yields only the timeout-error diagnostic replacement preserved here. Its timeout remains ten seconds. In the exact binary the leader poll is 8,208 bytes and its new diagnostic closure is 368 bytes before formatting callees. There is no evidence those diagnostics are the source of the megabyte-scale frame; removing them would conceal original errors without addressing the observed large frame.

The proposed source split must preserve exact owners, original request and phase identities, all assertions, invocation construction points, deadlines, workload and runtime thread configuration. It must introduce no spawn/detach, new authorization, stack-size change or retry. A coordinated successor compile should compare the new poll prologues before using one justified test run to validate behavior. This artifact alone is not a test pass or release qualification.
