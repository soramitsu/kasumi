# Required namespace policy caller replacement

This target-only three-file successor is stacked on the immutable48-file directory-fixed-maps cumulative proposal, not directly on the current Rust sources. Assembly owns NodeDiskConfig and all node_disk internals. This package owns only server persistent_disk.rs, runtime_memory.rs and docs/standalone.md. No actual source, release README/goal document, Rust build, native program or test was changed/run.

The generated new-installation policy directly emits required max_persistent_files=1,000,000, max_persistent_subdirectories=1,000,000 and census_work_per_step=1,000,000. Both explicit server fixture overrides directly set each field to the original16,384. The old combined field is removed from supported production construction. No serde alias, default, optional fallback or existing-installation migration is added. All byte quotas, memory budgets, handle limits, depth, name lengths and deadlines stay unchanged. The documented subdirectory count excludes configured roots; per-step census work is distinct from full-job logical file/directory capacity.

One added contract test uses the real generated RuntimeConfig's serde path: verifies the emitted numerical values, valid complete config roundtrip, rejection after removing each required field, rejection of a legacy-only policy and rejection of legacy plus new fields together. These are first-release configuration boundary checks, not a test of census algorithms. It has NOT been compiled or executed. The preserved dependency supplies deny_unknown_fields, and assembly's required field definition must land with this successor. Applying only this three-file package is intentionally not a coherent production build.

The complete current crates/scripts/docs scan (excluding immutable evidence and vendor implementation), overlaid with all48 dependency files and these three proposed files, finds no remaining legacy production caller outside assembly's internals. Two old-field string literals remain intentionally in rejection tests. The internal remaining references are explicitly listed for assembly; this package does not claim the combined internal implementation is complete. Runtime example_config routes through initial_config; kasumid example output, standalone initializer and the loopback fixture route through that generator or RuntimeStorage's new-installation/fixture configuration. Existing runtime/authority configs carry NodeDiskConfig directly. No independent static JSON policy was found in this audited scope.

Read-only target apply-check and application both pass and reproduce every proposed byte. Exact before/after current-source inventories and all48 dependency file hashes are retained. No Cargo/rustfmt/native execution was used; compilation, strict formatting/lint and the new serde test remain required coordinated gates after assembly integration. Logical directory admission and retained bank geometry, bounded census progress, directory mutation custody and filesystem growth qualification remain assembly/root implementation obligations; this caller change proves none of them by itself.
