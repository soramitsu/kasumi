# Canonical PageNumber decoding: source-pinned audit and migration design

Status: **DESIGN_ONLY_REQUIRES_COHERENT_DECODER_MIGRATION**. The production gap is confirmed and remains open. No implementation patch is proposed, because a branch-only checked decoder would leave a live alias-accepting path. Root explicitly allowed this bounded audit/design outcome when a safe migration exceeds the subtask. This package contains exact current bases, caller/effect inventory, a source-derived integer model, and the required integrated change/test plan. It is not a release acceptance record.

## Confirmed representation gap

`tree_store/page_store/base.rs:98` decodes all 64 raw bits but then discards bits40–58 and masks the page-index field to only `20 - order` bits. Thus different byte strings become the same PageNumber before any check can distinguish them. The test `base.rs::test::reserved_bits` explicitly asserts this acceptance. The raw allocator walker at `tree_store/allocator_state.rs:123` calls that decoder, so its cycle/range/payload checks do not reject a reserved-bit pointer to an otherwise accepted page.

The supported geometry is unchanged: a 20-bit region index, 20-bit order-zero page index and supported orders0–20. For order n, a canonical raw encoding must have bits40–58 zero and the low20 page-index field at most `MAX_PAGE_INDEX >> n`; test the supported order before shifting. Every remaining index bit is zero. Order31 already exceeds supported geometry and must continue to reject. No cap, region count, page size, allocator order, checksum scheme or writer byte format needs to change.

`alias-model.json` records 5,133 integer counterexamples derived from the exact current mask, across every supported order, three region boundaries and low/middle/high valid indices. There are `2^(19 + order)` encodings of each current decoded address, including the canonical one. This is a Python arithmetic demonstration, not Rust execution or a runtime validation claim.

## Exact decoder and effect families

`caller-inventory.json` lists all source matches with line numbers and original text, including tests/debug helpers. It contains seven PageNumber decoder references (four production sites, three tests), six BtreeHeader decoder references, 35 branch-child references and 47 allocator free/conditional-free/record matches. The counts include test and debug matches and are not claimed to be distinct production entry points.

The existing `TransactionalMemory::check_page_order` (page_manager.rs:584) is called by get_page, get_page_mut and mark_page_allocated, but only checks order after lossy decoding. Get_page then computes addresses and accesses storage. Mark_page_allocated validates layout and records the allocator mutation. The free paths at PageAllocator::free/free_if_uncommitted/conditional_free and TransactionalMemory::free_helper are currently infallible; free_helper mutates page tracking and the buddy allocator before computing the storage invalidation range. `try_save_allocator_state` also frees deferred/current-system pages into its snapshot before writing the snapshot. The exact inputs must already carry a canonical proof before any of these effects.

## Required coherent successor

Use one production PageNumber decoder. Replace its lossy body with a fallible canonical decode that first rejects unsupported order and both reserved-bit groups, then constructs a validated PageNumber without masks that hide a rejected representation. Remove the old reserved-bit acceptance expectation. Do not add a parallel checked API while leaving production from_le_bytes with its current behavior, normalize invalid bytes into a valid PageNumber, use a compatibility tag, or silently retry a different decode.

Keep canonical PageNumber values distinct from raw metadata. Restrict direct field construction to canonical internal producers (constructor assertions and private fields/proof constructors as appropriate). The raw representation must not enter PageNumber comparison, hashing, serialization, address calculation or allocator mutation before validation. This avoids widening PageNumber native layout merely to carry a corruption marker and makes infallible effect paths accept only a validated value.

1. Change BtreeHeader raw decoding to Result and propagate existing typed corruption. TransactionHeader and serialized-savepoint parsers already return Result and can propagate errors before root publication. Keep complete length checks before slice conversion. Preserve the original checksum-invalid slot bytes and the existing winner-selection protocol: an unusable checksum-invalid slot must remain quarantined opaque data, never decoded into a validated root, never accessed, and never rewritten as if it verified. Audit every primary/secondary-slot read before deciding whether to make slot parsing lazy or represent unusable roots explicitly. Do not fail an otherwise valid recovery solely because unused torn-slot bytes happen to set reserved bits.
2. The infallible Value boundary for InternalTableDefinition needs an explicit raw borrowed metadata wrapper with a fallible checked conversion. It must not construct a BtreeHeader or allocate decoded type fields before the relevant shape/root validation. Migrate all guard.value(), table-definition listing/checking, checksum/page walking and mutation paths in one change to consume that checked definition. Propagate failures through their existing Result/iterator item channels. A sentinel valid-looking table definition, default root, expect/unwrap on raw bytes or side decoder is not acceptable.
3. Make typed and untyped multimap subtree access fallible, using the same BtreeHeader decoder. Propagate through subtree discovery, checksum verification/finalization, relocation and all direct multimap consumers. Validate before publishing replacement branch/subtree bytes.
4. Make branch child decoding fallible or construct BranchAccessor only after a complete borrowed child-vector validation. Prefer the latter only if the type makes unchecked child access impossible: immutable page ownership must bind the validation proof, and all callers must use that constructor. Validate every child representation before mutators allocate or write a replacement branch. Debug formatting must render corruption without normalizing it or panicking. Propagate through child_for_key and cursor/range iterator APIs; do not map malformed child bytes to missing-child Option.
5. Extend PageList::checked to validate every used page-number entry before returning its immutable proof wrapper. Leave writer-permitted unused padding untouched. Its get method may return canonical PageNumber infallibly only through that existing slice-bound proof; do not reintroduce an unchecked public raw decoder to achieve this. Validate the entire selected historical prefix before extraction/removal/free or allocator-snapshot effects, preserving current preflight ordering. Existing InvalidPageList can remain the record-level rejection class; canonical standalone PageNumber errors use existing Corrupted, never a new capacity denial.
6. Raw allocator traversal must use the same canonical production decoder for its root and every child. Preflight the complete branch pointer vector before following even the first pointer, just as it already preflights separators. Only after representation success should it check depth/cycle/routing/payload and resolve pages. An invalid later child must not cause earlier child records to be processed first.
7. Re-audit every serializer/comparison/effect match in the frozen inventory. Valid producers remain byte-identical. If an effect API can still receive an unvalidated value, convert that boundary to Result and propagate before the first effect; do not add assertions that turn disk corruption into an unwind. Keep the typed canonical representation smaller than a general full-memory ownership claim.

These items are one migration prerequisite, not optional decoder alternatives. The difficult boundary is the infallible internal Value conversion and its mutation callers; an allocator-branch-only patch would violate the user's first-release rule. A deferred invalid marker is also not a safe bounded shortcut unless all comparison/serializer/free boundaries propagate it correctly; otherwise it merely moves the panic, alias or normalization.

## Required verification before integration

- For every supported order0–20, canonical producer values at region0, region1 and MAX_REGIONS-1 and index0/middle/maximum must decode and re-encode exactly. Use actual allocator-produced pages in addition to arithmetic representatives. Preserve native allocation/free/resize producer tests and maximum supported geometry; do not invent a smaller test-only accepted cap.
- Independently set every forbidden high bit40–58 and every order-dependent forbidden index bit, plus combined masks. Each must return typed corruption. Existing reserved_bits acceptance must be replaced by rejection. No invalid decode may allocate a page-sized buffer or reach storage.
- Use a counted backend to test raw allocator root and first/later branch child aliases. Reserved-bit rejection must occur before access to the aliased target, before any child-record callback for a malformed vector, and before live allocator mutation. Preserve valid branch routing, cycle, snapshot/current/stale-layout and payload tests.
- Corrupt present roots in canonical transaction headers, internal table definitions (including allocator-state table), savepoints and typed/untyped multimap subtrees. Recompute surrounding checksums where needed so the representation check itself is exercised. Assert the original typed error, unchanged durable bytes, unchanged write/admission/read-target counters, and retained original owners where the opening/transaction contract requires them.
- Preserve valid current-format recovery with an unused checksum-invalid slot whose opaque bytes include reserved bits; never serialize that slot as newly valid. A checksum-valid selected alias must reject before page access. Assert both slot orders and positive winner layouts.
- Put a malformed used page number in the first and last record of a selected DATA prefix. Assert no extraction, staged reclaim, buddy/tracker mutation or post-commit free occurs. Retain legitimate nonzero unused padding and allocation-free record preflight.
- Cover branch-copy/merge/relocation and cursor paths that formerly called an infallible child accessor: no mutation before detecting a malformed later pointer. Keep complete public targets, strict vendor checks and existing checksum tests for the final integrated source, coordinated by root.

No tests in this package execute Rust. Its integer model confirms the current normalization gap only. Full reachable-root allocation ownership, duplicate/overlap ownership across trees, root-layout extent validity, maintenance physical reserves and total memory/workspace remain separate open requirements.
