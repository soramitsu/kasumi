# Managed child namespace successor: bounded design

This is a separate target-only successor to the frozen 49-file census package. No actual-source edit, native job or Cargo gate is authorized while root143 owns that window. The primitive/caller migration is incomplete; this document records the concrete ownership shape before implementation and disjoint caller edits.

## Capability and geometry

Proposed methods are `NodeDiskDirectory::open_child(&CStr)`, `create_child(&CStr, DiskWork)`, and consuming `remove_if_empty()`. Names must be one normal nonempty component, not dot/dotdot, contain no slash and fit max_name_bytes. Existing enrolled children are opened exactly; `AlreadyExists` never authorizes a raw inode's adoption. Configured roots cannot be removed or recreated by these methods. Child directory levels must fit census's unchanged root-inclusive max_depth.

Keep F, D, R, H, work-per-step, all existing byte policies and deadlines unchanged. Before any mkdir effect, prove D capacity, one future operational directory-owner slot, and the absent-insertion certificate in the existing F+D+R fixed bank. Reserve the child's full required DirectoryPolicy extent plus existing affected-parent promises under the same NodeDisk/DeviceDisk boundary. No third map or post-effect growth allocation is allowed. Existing directory policy remains mandatory but physically unqualified: it is an operator ceiling, not a proven kernel allocation maximum.

Generalize the existing internal FileParent into retained parent custody usable by file and directory owners, with no compatibility alias. A non-root DirectoryOwner must own its exact parent FD and bounded ancestry alongside its child FD. Charge its ancestry allocation explicitly in the type-derived directory-owner envelope. This is one directory owner under H, with two retained descriptors, matching the analogous file-owner model. The root owner needs no parent. Parent live_handles track these actual retained references; they do not consume a second independent operational directory quota.

## One owned unresolved namespace operation

A mkdir can succeed before child open/stat/sync fails. A rmdir can take effect before parent sync/verification fails. The post-effect path therefore needs actual operation custody before the syscall, not merely a numerical reservation or eventual lookup of a path.

State will have one inline optional pending-directory operation. State serialization excludes two preparations; any uncertain outcome moves phase to Failed and seals the device, excluding another operation until explicit census resolves it. The prepared operation owns its bounded root/name components, exact namespace binding and parent ancestry, affected-parent plan, preallocated child-owner backing, actual retained parent/optional child descriptors, cardinality/extent reservation, operation kind and original native phase/outcome. The existing extra prepared-directory-owner envelope funds this one retained workspace; inline fields are covered by type-derived NodeDisk size. No additional map, failure-time allocation, detached task or leak-only resource transfer is used.

For removal, consuming the last NodeDiskDirectory Arc retires its control allocation before moving the concrete owner into this operation. Aliases must reject before namespace effects. A move transfers actual slot/resource ownership; it does not return capacity while the pending record retains its backing. Native descriptors, path allocations and other concrete backing must retire before any corresponding slot/byte credit can become reusable.

A definite no-effect syscall failure may restore the prepared parent and child reservation only after exact retained-descriptor checks prove the original physical parent snapshot. An unknown existing raw entry, altered ancestry or uncertain sync cannot take that rollback path. On success, exact child/parent identities and same-device private type checks, child synchronization, affected-parent synchronization and prepared-parent settlement precede healthy publication. An observed child/parent extent beyond its pre-admitted ceiling must be fully recorded when known, retain original reservations and fail the shared owner; it is not a successful physical-bound test.

Returned error/unwind retains the original operation and exact binding under State with its funded backing. A known child identity may have an unsettled ledger entry; an unknown post-mkdir child still has its logical slot, original binding and reserved envelope represented by the pending record. The old active ledger and shared promises remain conservative. No generic open or raw absence observation silently resolves the operation.

Explicit reconcile is the resolution boundary. It first requires all external operational owners/cursors to drain, then retires this known internal operation's actual descriptors under retained root custody before a candidate census may release unlinked physical resources. The original operation/diagnostic metadata and its reserved prepared-owner workspace remain owned until complete candidate/shared-promise acceptance. Failure/cancellation preserves them. Success swaps the already-funded candidate, retires the pending metadata/backing, and only then reopens admission. A native resource with genuinely uncertain close cannot be treated as drained; it retains custody and requires restart according to the native close contract.

## Caller migration and remaining design edge

Authority's frozen 44-site audit remains the inventory. First migration targets are `backup_sessions_fs`, filesystem backup destination initialization, and filesystem audit archive initialization. A raw Directory(File, Arc<NodeDisk>, PathBuf) must become a counted directory capability plus its logical path. No raw FD export is proposed. `check`, sync and child operations must use the enrolled owner. Backup intent/outcome/session identity tombstones remain permanent; objects GC never removes session history.

Local recovery archive cleanup must collect its original bounded canonical page, explicitly close the enrolled cursor with secondary-close custody, then delete. Target recovery cleanup retains its three-entry whitelist, permanent stopped-generation record, exact journal/inode/digest checks and no generic recursive remove.

A component-wise rooted-path helper still needs a concrete caller contract before signature freeze. In particular, a new backup session consumes a UUID directory and an objects directory, and needs its corresponding file slots. A per-child primitive alone must not be presented as proving whole new-session admission before effects. The caller's finite missing-prefix/record preparation must reserve the complete required set before its first new-session effect, or the remaining multi-component admission requirement must stay explicitly open. Existing prefix directories may be reused only by exact enrolled identity.

Bootstrap/private/external-output scopes in the audit are distinct from post-enrollment managed descendants. No fallback raw branch or inferred new root is permitted. Physical pre-effect directory bounds, native/allocator bounds, whole-server RSS plus reserved high-water fit, full managed caller adoption and integrated gates remain open.
