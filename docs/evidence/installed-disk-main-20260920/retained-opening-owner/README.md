# Retained opening owner prerequisite

TARGET ONLY. No actual Rust/Cargo edits and no compiler/native execution by this agent. The package is not yet compile-qualified or production-adopted. The source base is master under /Users/mtakemiya/dev/kasumi; the page_manager baseline includes applied149's checked allocator length planning. No alternate worktree is used.

The new RetainedDatabaseOpening owns the provided raw backend before its first redb storage effect. PagedCachedFile cache geometry/allocation preparation borrows that raw backend slot, then takes it only after all preparation succeeds. TransactionalMemory initialization borrows the installed cache and leaves that actual cache installed on every error/unwind. It takes the cache only as the final field of successful memory construction, after preparing the other fields. The resulting memory is installed before winning-root verification, allocator loading/repair and arbitrary repair callbacks.

Database construction transfers that exact memory to RetainedDatabase. The bootstrap WriteTransaction is immediately retained before repaired-root assignment or persistent-savepoint restoration. The opening observation covers construction and bootstrap body; terminal, rollback and disposal remain the original separate RetainedWriteTransaction observations. A settled refused commit is not a successful open. Ready requires successful terminal return and actual transaction disposal. A failed bootstrap never exposes the internal database through either public accessor. The matching retained witness is available only while Ready or WaitingForTransactions, allowing actual user transaction disposal without granting new access after closing starts.

Close seals access, explicitly aborts an unstarted bootstrap once, and requires actual disposal before closing a constructed database. Earlier phases directly observe partial backend release without checkpointing incomplete state. Opening phase is saved separately so closing cannot erase the failure location. Repeated calls do not replay an original terminal operation. Both original opening and close outcomes stay owned, including simultaneous failures or panics.

The OpeningAdmission proxy holds the exact original admission Arc as its inner field. It is a distinct Arc/control block, not pointer-identical to that original object. All actual growth/settlement calls forward to that same inner owner. On uncertainty, its own atomic failed latch is set before invoking the original owner_failed callback; subsequent check/growth/settlement refuses even if that callback panics before fencing its own object. The callback enters once. A catch at this exact boundary retains its panic and returns normally, allowing CheckedBackend::io to return its still-live original I/O error instead of dropping it during callback unwind. Its OnceLock is observed only with get, never wait/get_or_init; callback-in-flight is reported as Entered. A Send-only panic payload is kept in a private mutex, borrowed using try_lock; concurrent diagnostic borrowing reports unavailable rather than blocking or exposing mutable payload ownership. Neither the caller nor a repeated close can erase that original payload.

Builder's repair callback directly becomes Fn + Send + Sync. The four supported call sites found in crates/vendor are no-capture or atomic captures and need no source adaptation. This is necessary for real shared census custody and fixed process-static retention tests; thread-local custody would dispose of an uncertain owner when its test thread exits. No non-Send fallback is added.

Six proposed FileBackend tests cover effect-free preparation, close-before-open, first actual I/O plus secondary close failure, initialization write unwind, repair callback unwind, successful repaired commit/disposal and clean reopen abort, reader-held close, and simultaneous original I/O/admission-callback panic with proxy fencing. The two uncertain native files remain in fixed process-static slots. Tests are PROPOSED and UNRUN. The fault matrix in fault-test-design.md still requires additional native coverage before full opening acceptance.

This patch does not supply the mandatory installed census, charge the proxy Arc or cache/memory owners, bind arbitrary error/panic allocation budgets, account native synchronization/RSS, or migrate the twelve production commits/two initialization sites. The existing consuming database constructors are not made safe by this prerequisite; their production use must be directly replaced as part of the coherent adopter. They cannot serve as a fallback once the mandatory owner boundary is installed. StorageBackend creation/locking predates this primitive and must itself occur under the embedding census's prepublished owner. Process abort/OOM and double-panic abort do not yield recoverable reports.

No guarantee is inferred for arbitrary in-flight operations merely from a wrapper type. Parent/child owner inventory and actual object destruction before reservation-credit release remain caller obligations. Positive Closed denotes observed physical release, not released diagnostic allocations or complete process drain.
