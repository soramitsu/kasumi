# Independent retained-opening review

Reviewed the frozen revision2 ten-file patch and revision3's explicit delta. **Approved for scoped compilation/native validation; not a production-adoption, memory-bound or release acceptance claim.** No additional blocking semantic defect was found in the reviewed opening/terminal/close protocol. The new tests are proposed and unrun at this review boundary.

The exact raw backend remains in TransactionalMemoryOpening until PagedCachedFile finishes geometry/cache preparation. CheckedBackend construction is a field-only transfer, with no initial backend call after taking that source slot. The cache stays in its retained slot during fallible memory initialization; debug allocations/native mutex preparation and conversions precede the final cache move. The memory Arc is installed before winning-root, allocator restoration and arbitrary repair callbacks. The later memory-to-Database transfer and inline retain contain no fallible storage phase after taking the prior memory slot. Allocation abort/double-panic abort remains excluded as documented.

The bootstrap transaction is installed before repaired roots or savepoint restoration. Begin-write itself still uses ordinary local guard/cache preparation while the physical Database/memory remains retained; this patch does not prove each local metadata allocation has a prepublished budget. A body failure retains that transaction for explicit abort/disposal. Original begin/body errors and panics remain stored separately from bootstrap terminal, rollback, disposal and physical close. A failed terminal cannot become Ready merely because rollback/disposal succeeds. The opening-phase marker survives Closing, and a matched user transaction can dispose while WaitingForTransactions without reopening database access.

OpeningAdmission wraps the exact inner admission Arc rather than claiming proxy pointer identity. Its atomic failure latch precedes the original callback; the winning invocation records callback return or the exact Send panic payload. Catching at that call boundary allows the already-live original I/O error to return into retained opening/transaction observation. Diagnostic access uses OnceLock::get and a try-locked payload; it does not wait for an in-flight callback or move the payload out. No repeated terminal/rollback/backend-close attempt is authorized by this wrapper.

The eleven tests include actual FileBackend locks and original marker/pointer preservation, successful repair followed by committed-root reopen, terminal refusal with positive rollback/disposal, rollback failure, commit I/O failure, actual malformed savepoint restoration and disposal of a retained user writer while close waits. Several faults are armed at the private begin_open/finish_bootstrap boundary and therefore establish phase-unit behavior rather than a full fault sweep. Four deliberately uncertain fixtures are retained in fixed process-static slots. The proposed callback Send+Sync bound is direct; no thread-local fallback was introduced.

Revision3 changes only honest non-exhaustive Debug output, pointer-expression syntax, and the root-reviewed cached-file conversion/lint successor. The checked lock-stripe conversion remains before backend transfer. I verified the exact revision2 base/proposed hashes and application, then applied the revision2-to-revision3 delta to the reviewed proposed tree and checked every revision3 proposed file hash.

The package does not yet register actual opening owners in the mandatory installed census, admit the proxy Arc/cache/metadata/native synchronization workspace, bind arbitrary diagnostics or callback execution time, migrate consuming production constructors, or dispose final diagnostic allocations before memory credit. These remain required independent implementation/adoption work. Native compilation, full retained opening faults, strict Clippy and public integration evidence are required after composition with other pending source changes.
