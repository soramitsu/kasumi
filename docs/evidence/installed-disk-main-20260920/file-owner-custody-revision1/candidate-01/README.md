# File descriptor custody candidate 01

This is an unapplied, target-only successor to the frozen `backup-namespace-admission-revision4/proposed` source. The eight-file `custody.patch` and `manifest.json` bind exact bases and results; copied `git apply --check`, application, and byte readback passed. No actual repository source or frozen predecessor was changed. Rustfmt passed. Compilation, runtime, strict Clippy, independent implementation review, and broader integration are pending.

The candidate allocates a fixed checked H+1 custody bank during installed metadata admission. A preparation holds State while constructing names, ancestry, owner Arc storage, and initialized mutex backing, then reserves its slot before its first descriptor. Every acquired file or walk descriptor is installed before metadata checks. File leaf verification uses a single-component `fstatat` with `AT_SYMLINK_NOFOLLOW`, preserving inode, device, type, link-count, owner and permission checks without acquiring another leaf descriptor.

File and publication preparation guards explicitly close descriptors on terminal failure or abandonment. Failed payloads retain their original outcomes and actual backing in the installed slot. A live owner has the same fixed slot; native close failure or an unwound retirement retains its registration and exact Weak backing. Native close is attempted once. Its original `io::Error` and diagnostic descriptor number remain retained on uncertainty; that number is never retried, and the uncertainty prevents census reopening. Close errors from data, parent and walk slots are retained independently of the operation's original failure.

A successful full census after external-owner drain is the explicit relinquishment boundary for already terminal retained attempts. Cancellation or a rejected candidate cannot destroy their diagnostics/backing. Unknown close outcomes cannot reach that boundary. Candidate publication retires actual retained resources and the original Weak allocation while State and shared device promises remain serialized, before reopening admission. This does not acknowledge a live operation: published external owners and namespace witnesses still prevent census.

Known geometry includes `allocation<Slot>(checked usize(H)+1)` and the existing size-derived owner, directory-owner and NodeDisk inline structures. The file envelope adds three initialized native-mutex allowances per H+1 slot beyond the inherited Budget allowance, conservatively covering two simultaneous parent Walk mutexes plus the original-outcome mutex. Parent ancestry/name/Arc backing keeps its existing admitted owner/preparation envelopes through transfer. The empty post-retirement placeholder contains no mutex allocation. The inherited per-allocation and per-mutex platform allowances are not an allocator/RSS proof; arbitrary opaque report payloads, panic payloads and the whole caller envelope remain separate qualification work. No handle, file, depth, byte limit, or 2 GiB policy is reduced.

The shared parent type retains the existing directory `verify` and `retire` entry points. File callers use only `verify_file` and `retire_drained`. Configured-root acquisition, ordinary DirectoryOwner closure, and the inherited directory verification destructor protocol remain separately unqualified; this candidate does not claim to repair them.

Four proposed regressions cover unknown preparation close without retry, the same retained error object's address across a canceled census, verification-walk close failure retaining registered custody, and an unwind between data close and parent/backing retirement. Existing file assertions now distinguish retired native descriptors from still-admitted failed owner backing. The four earlier adversarial fixture-order corrections are composed from their separately frozen package with exact function hashes in `fixture-composition.json`; both before- and after-preparation branches remain.

`native-03` is the prepared serial qualification cohort. It retains all 67 prior namespace/session module cases and adds 64 exact file/custody cases (including the four new regressions), for 131 selected names. Five existing ScratchDisk/NodeStore integration cases are explicitly omitted rather than stubbed; five inherited device cases remain compiled but filtered as before. Existing exclusions of directory/namespace integration modules and three authenticated GC methods remain recorded. A binary-name inventory must match before the selected test execution; production geometry still reports unqualified RSS headroom. Each of the six phases keeps a 120-second limit and records process-group drain and source/executable hashes. The source and runtime dependencies are inventoried before and after native execution.

`native-01` and `native-02` preserve two source-only preparation failures: the inherited result parser missed a multiline geometry result, then AST validation caught a generated newline escape. No compiler or native process was dispatched for either attempt. The corrected `native-03` runner passes AST validation and all 98 source-copy bindings read back unchanged. It has not been dispatched.
