# Bounded directory-owner foundation review

Read-only review of the evolving proposed sources in `../directory-owner-foundation/proposed`, principally `node_disk/directory.rs`, `census.rs`, `memory.rs` and `node_disk.rs`. These files were not modified or built by this reviewer. This is not review of namespace mutation/caller adoption, which the proposal explicitly excludes.

The actual descriptor closes before operational drain counters are decremented. Paused admission blocks new opens, preserves existing read/sync custody, and refuses reconcile while either a file or directory owner remains. Directory ancestry verification checks the enrolled binding, parent identity, inode, private permissions, length and observed extent at every step. A healthy final absence requires verified enrolled ancestry and an unknown final binding. Census directory charges are kept separate from sparse-file promises and replacement census retains old accounting on failure. No cancellation-detachable async child is introduced by these synchronous operations.

Actionable memory-order finding sent to the author: `DirectoryOwner::drop` decrements `state.open_directories` and unlocks state before Rust drops its `root`, `names` and Arc backing. The formula funds only `max_open_directories + 1` owner envelopes. Concurrent destructors suspended after returning slot credit can overlap further admitted generations while their variable backing is still allocated; the single-extra-owner allowance does not establish a bound on that retired backing. Free variable backing before publishing slot credit and define how the owner allocation remains charged/retained through reclamation. A post-credit/pre-backing-release fixture barrier can demonstrate the problematic interleaving. This concerns the new operational-directory owner, not approval to weaken physical drain checks.

Root labels are explicitly bounded by `max_name_bytes`, so the copied root-name path allowance is not itself an unbounded-label issue. The strict ledger must remain unadopted by managed file mutation until parent-directory settlement exists, as the author already documents. Existing file operations change parent namespace metadata; making this new verification unconditional there would otherwise fence legitimate writes.
