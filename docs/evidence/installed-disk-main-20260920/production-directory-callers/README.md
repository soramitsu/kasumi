# Production directory caller inventory

This is a read-only current-source audit and a migration checklist, not an applied directory implementation or a qualification result. The workspace is `/Users/mtakemiya/dev/kasumi` on `master`. No actual Rust source, release document, Cargo target, native program or lifecycle workload was changed or executed for this audit.

`inventory.json` identifies 28 caller groups containing 44 production call sites. Each row records the current path, exact line and source text, physical parent/root, enrollment phase, required managed capability and semantic constraints. Shipped benchmark and example code is included and explicitly distinguished from installed server/library storage. The scan covers all 499 Rust files under `crates`, including test files; it does not assert coverage of external consumers or vendored dependency implementation. `classified-search.json` accounts for every one of the 209 raw match lines. The exact search, supplementary searches and source hash inventories are retained.

The ordinary installed namespace mutations are concentrated in backup session children, filesystem backup/archive destinations, recovery generation and archive directories, and recovery startup. These require direct mandatory managed directory capabilities once their parent is enrolled. Raw creation during explicit first installation is a separate boundary: its ordering and custody must be established, rather than inferred merely because a local `NodeDisk::open` call appears later. Signer startup can share an already installed RuntimeStorage owner. Operator, TLS and profile directories are outside the default data/backups roots; silently enrolling private key material into the ordinary data namespace is not an acceptable shortcut. Caller-selected export/report paths also lack a general overlap exclusion, so they cannot be assumed external without a checked boundary.

No production `remove_dir_all` or `unlinkat(AT_REMOVEDIR)` call was found in the audited crate sources. Current installed removal is the exact recovery target/archive `remove_dir` paths. Production `unlinkat` calls found here use flags zero for regular files. Benchmark TempDir destruction is recorded separately: implicit recursive temporary-tree cleanup does not qualify installed cleanup custody. The supplementary search checks alternate syscall/wrapper spellings and renames; absence from those patterns is bounded search evidence, not proof about arbitrary future wrappers.

The current raw scanner's ignored `closedir` result and its total-work/file-count conflation remain visible. The frozen directory-cursor proposal already covers the bounded backup listing replacement; this inventory does not duplicate that implementation. Managed mkdir/rmdir signatures remain with the assembly agent. No caller patch was prepared before those signatures stabilize. `migration-checklist.md` records the required caller behavior, and `census-restart-policy.md` separates the current defect from the approved first-release policy replacement.

Every source line cited in the inventory was checked against the captured source. All 499 source hashes must match before and after the audit. The manifest records the result. All counts are source observations, not tests or a memory/physical-growth proof.
