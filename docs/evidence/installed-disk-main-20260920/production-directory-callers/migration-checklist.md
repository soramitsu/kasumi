# Mandatory caller migration checklist

## Installed persistent namespaces

| Priority and current caller | Physical parent and child | Required migration and preserved contract |
| --- | --- | --- |
| `backup_sessions_fs::Directory::child` | backup root / `sessions` / canonical nonnil UUID / `objects` | Carry an enrolled directory capability, create each counted child with custody admitted before effects, or open an exact enrolled existing child. `AlreadyExists` alone must not adopt an inode. Preserve private uid/mode, no-follow descent, captured ancestry, child and parent synchronization, and original uncertainty. |
| `backup_sessions_fs::Directory::list` | exact session `objects` directory | Use the frozen bounded cursor replacement, original 1..256 page limit and limit+1 selection. Authenticate abort proof per entry; canonical nonnil UUID `.kasumi` names only. Explicit close must preserve an independent original close failure. |
| `FilesystemBackupDestination::new` | configured destination under an installed backup root | An identical configured root must already be enrolled; an absent descendant requires its enrolled parent. Preserve existing one-level creation semantics, max bytes and private directory validation. Do not recreate an absent installed root. |
| `FilesystemAuditArchive::open` | durable directory / `audit-archives` or `tenant-audit-archives`, or configured archive parent | Direct managed open/create, exact inode identity, child/parent sync. Current create-error handling can continue when private-directory checking succeeds; a new boundary must retain original phase outcomes instead of hiding a failed physical step. |
| `TargetRecoveryRuntime::open` | installed `generation_root` below a configured root | Replace raw recursive creation with bounded component-wise managed descent/creation. No intermediate symlink traversal or unowned partially created chain. Account and synchronize each changed parent. |
| `local_recovery::Operator::prepare_directory` | database parent / `generations` / target-incarnation UUID | Preserve exact journal operation/target reservation and `binding.json`. This precedes database `CreationDispatched`, so directory effects need their own pre-effect custody. An empty crash remnant still requires exact namespace reconciliation and journal ownership. |
| local recovery target empty/list/cleanup | target-incarnation directory | Preserve the three-entry whitelist: `binding.json`, `node.redb`, `tenant-audit-archives`; refuse unexpected names, links and wrong bindings. Close cursors and child/file owners before consuming empty-directory removal. Require the matching permanent stopped-generation record. |
| local recovery archive create/list/cleanup | target / `tenant-audit-archives` | Preserve journal `DirectoryIdentity`, exact object row, canonical UUID `.audit`/`.audit.pending`, staged/published inode checks, ciphertext byte/hash checks and the 64 KiB hash buffer. Retain original PAGE=256. Collect one bounded page, explicitly close it, then mutate; deletion while a managed generation-checked cursor is open invalidates that cursor. Repeat using the same stopped-operation journal. |

A managed `remove_if_empty` must retain the exact child, parent ancestry and original remove/sync phase outcomes. No generic recursive deletion is needed by these production paths. If a prior uncertain removal is later observed absent, absence is not a substitute for the required parent durability settlement. If an intermediate parent is absent, settlement/reconciliation must use the surviving installed ancestor and original owner; it must not invent success or replay uncertain effects.

## Permanent backup session identity

`Directory::put` creates `sessions/<session>/objects` even for intent/outcome publication. A new distinct session therefore adds two nonroot directories, plus the shared `sessions` directory once. A completed/aborted session retains `intent.kasumi` and `outcome.kasumi`; the original aborted-object reclamation removes only authenticated objects. `backup_sessions.rs` explicitly verifies those records remain after GC. An incomplete session, temporary upload or uncertain operation can retain additional charged resources and must be counted from actual custody, not from this steady-state description.

Do not delete a session directory, intent or outcome merely to fit directory/census limits. That would lose the permanent identity that rejects or resolves late writes. New-session admission must reserve its actual directory/file slots, growth and owner memory before effects. If the fixed capacity is exhausted, reject before creating a new session while allowing already admitted exact cleanup/resolution to settle. One directory per root and two per new session are logical slot counts, not physical extent or RAM coefficients. Parent growth, transient files, terminal outcomes, allocation retirement and fixed bank occupancy still need the separate implementation proof.

## Explicit installation and private/output scopes

* `standalone::initialize_owned` creates a new installation root and fixed `data`, `operator`, `tls`, `profiles`, `backups` children before first data/backups enrollment. Preserve exclusive first installation and refusal to adopt an interrupted populated installation. This bootstrap requires its own actual custody before filesystem effects.
* Signer verifier initialization must resolve whether the shared RuntimeStorage already owns the configured root. Merely calling its local open later does not authorize a raw descendant mutation.
* Standalone tenant staging under `operator/tenant-stage-<operation UUID>` already persists `Dispatched` before creation and permanently retains failed stages. Preserve its exact two-file contract and bounded three-entry detection. It needs an explicit private-root capability, without putting private material into ordinary data backups.
* Certificate rotation scans `profiles`; preserve profile selection and pin semantics while adding an admitted bound and explicit cursor settlement. Its current full scan is not bounded by the installed data-root policy.
* Admin/key recovery exports and report output paths need an explicit external/private output boundary. Where a caller chooses a descendant of an installed root, route through the corresponding managed parent; do not silently bypass enrollment.
* ScratchDisk root bootstrap is separate from persistent NodeDisk and forbids overlapping roots. Its memory/registry charges precede creation, but failed create/sync publication still requires retained bootstrap custody.
* Benchmark temporary roots, Bao processes and reports are developer-owned scopes. Preserve their process/owner drain before TempDir cleanup. The live benchmark size traversal occurs before DB shutdown and is not an installed directory accounting proof.

No compatibility alias, fallback raw directory branch, inferred new root, deadline increase, quota increase, or lowered workload is part of this checklist. Caller migrations should be direct once the managed primitive and its admitted work/ownership contract are concrete.
