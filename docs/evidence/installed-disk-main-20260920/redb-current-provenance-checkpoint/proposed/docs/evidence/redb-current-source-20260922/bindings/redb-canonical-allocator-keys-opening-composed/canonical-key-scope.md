# Reject noncanonical allocator-state keys before typed traversal

Target-only six-file candidate. No actual source, Cargo or native process is changed/run by this package. It is separate from the encoded-length and single-buffer encoding patches.

The old `AllocatorStateKey::Deprecated` variant, tags0..=2 decoder mapping and tag0 writer are removed. Canonical keys remain exactly five bytes: tag3 plus the little-endian region index, tag4 plus four zero bytes, or tag5 plus four zero bytes. Unknown/old tags, wrong widths and nonzero singleton padding return existing `StorageError::Corrupted` through checked parsing. No obsolete variant, alternate writer or compatibility decoder remains.

A new raw allocator-state tree walk validates all leaf keys and branch separators before constructing/accessing the typed allocator-state tree. It knows the mandatory fixed-five-byte-key/variable-value representation and bounds-checks page headers, counts, key ranges, child ranges and monotone value ends. It never calls the allocator key comparator or infallible Value decoder. Keys must be strictly ordered across leaves and within branch separators; duplicates and aliases are corruption. Every transaction-stamp value must be exactly eight bytes before any stale-snapshot decision. The existing point lookup also replaces its stamp `try_into().unwrap()` with a typed corruption result as defense in depth.

The walk retains an inline path bounded by the existing MAX_BTREE_DEPTH=128 and rejects cycles on that path. It does not collect keys, pages or rows. Reads still use the real cache/physical owner, and recursion retains ancestor guards; no total memory or stack bound is claimed. Existing raw page-width/type metadata checks happen before this walk. Buddy/tracker value decoding and region-index/layout correspondence remain separate validation obligations; this patch validates key representation, page access geometry and stamp length, not every allocator payload bit.

Validation runs before typed allocator lookup, unclean winning-root verification, repair allocator reset/callback progression, and read-only unclean refusal. Thus unsupported keys cannot be silently skipped by the Region range, mapped to an alias, or treated as a stale snapshot to rewrite. Integrity reload preserves its existing sync/discard behavior and rejects before allocator reconstruction/header normalization. Missing or well-formed but stale snapshots retain the original verified repair path. A full allocator scan is not added to every ordinary begin_write: opened roots have been validated and the sole production allocator writer emits only canonical keys.

The internal `Value::from_bytes` interface is infallible. It retains an invariant panic if invoked outside that validated boundary with malformed bytes; no production on-disk key reaches it before the raw validation. The private fault-fixture writer deliberately bypasses canonical publication only under cfg(test).

Seven prepared tests cover accepted key roundtrip and zero-allocation successful checked parsing; rejected old/unknown tags, widths and padding; real clean/unclean files rejected by writable and read-only open with zero repair callbacks and unchanged bytes; malformed stamp lengths rejected before stale repair; integrity rejection with unchanged storage; valid stale-stamp repair as a positive control; truncated/invalid leaf geometry; and real in-memory leaf/branch pages demonstrating invalid branch separators and cycles return corruption without typed comparison. Tests are prepared, not executed. Existing checksum, fault, lifecycle and public integration gates remain required.

Target rustfmt and apply-check are the only executable static checks here. The first formatter invocation could not resolve omitted module children in the narrow target snapshot; it exited1 without any compile/test. The successful invocation explicitly used skip_children=true and formatted the six proposed files. The manifest pins exact bases, proposed files, helper entry points and static checks for parent review/application.
