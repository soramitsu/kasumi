## Findings and corrections

1. **Same-length file extent changes escaped validation.** The original cursor checked EOF but not physical allocation/pending extent, allowing a raw write to materialize a settled sparse file at unchanged length. The frozen code derives actual extent and applies the existing retained-file predicate: exact known EOF, EOF within reservation, actual bytes within admitted allowance, and exact durable-record equality when settled. Unsettled admitted growth retains its existing allowance without releasing credit. The new regression asserts unchanged EOF, an actual st_blocks change, InvalidData, and failed owner. No silent enrollment is added.

2. **Early stop discarded an independent native close failure.** The original stop(kind) discarded finish()'s error. The frozen cursor retains native ErrorKind and errno inline as NodeDiskDirectoryCloseError, independently of the primary read/cancellation kind. Repeated close observes the same native outcome; next preserves the primary error first and otherwise returns the retained close error before considering EOF. Native closedir errors have no opaque Rust payload to preserve, so this inline representation retains the native failure identity available here. The cancellation-plus-close regression checks both outcomes and retained stream count.

3. **A partial backup page could report success after failed close.** Listing formerly broke after limit+1, dropped the cursor, and returned a successful page without observing closedir. The frozen caller evaluates its ordinary validation result, explicitly closes regardless of that result, then drops directory custody. A successful page requires close success. If listing and close both fail, the returned anyhow chain retains the original listing error and the original independent io::Error. Authentication, canonical object-name checks and the limit+1 selector policy are unchanged. The explicit failed-partial-close regression checks that close failure cannot become a later successful EOF. Full backup caller integration is still unexecuted.

## Ownership and synchronization

The consuming constructor requires exclusive private directory custody. Stream creation uses an independent openat(".") file description, verifies enrolled ancestry/identity before fdopendir, and handles fdopendir failure by closing the still-owned fd. No inner Arc/Weak or raw descriptor escapes. Returned CStr names borrow mutable cursor access, so safe callers cannot advance/close the stream while retaining that borrow.

Successful closedir completes before the stream count is decremented; the independent DirectoryOwner survives until afterward and its existing private-Arc retirement frees backing before its count. The close-gated test observes the real stream fd no longer naming the inode while the directory fd and both counts remain retained. State guards are released before stream retirement and there is no production caller callback under these locks.

Uncertain close never retries a possibly consumed DIR. It fails the disk, retains stream credit and conservatively leaks one existing strong NodeDisk reference without allocating. The process-static strong installed registry already keeps successful NodeDisk owners funded; the additional reference is therefore conservative, not evidence that the registry alone was insufficient. At most the already admitted live cursor count can enter this failure path, and the failed owner cannot admit new cursors. This is retained uncertain resource custody, not a claim that the unknown native resource drained or can be recovered. The regression verifies retained owner/charges, but cannot distinguish the extra Arc from the existing strong registry root.

Managed namespace changes advance a checked generation during successful settlement under State. A cursor sees a mismatched generation before another entry and returns sticky WouldBlock without treating the managed change as corruption. Cancellation remains Interrupted. Both actual directory and stream counts block reconcile, preventing census/operational stream overlap. Capacity uses existing max_depth; file/directory limits are unchanged.
