# Proposed staged cancellation test boundary fix

Status: proposed, unapplied, not compiled. This is a first-release direct test correction prepared only under the main/master checkout's target directory. No production behavior, deadlines, outcome assertions, or capacity limits change.

`Database::submit` awaits `staged_operation_read` before preparing and starting its proposal. `read_staged_identity` can suspend awaiting its blocking point read. The failing tests polled that outer request once and treated any `Pending` as proof that the proposal registry owned a write. Dropping the request at this point cancels its preflight, so no write was admitted. `WorkFence::drain` waits for the registered read to release its registration; it cannot create a proposal or its permanent outcome. This explains both the missing valid stop and the unresolved finalize.

The proposed test-only registry counter advances after `start_result` succeeds and the actual worker is stored in its slot. Its checked next value is computed before spawn. `wait_for_admission` captures that monotonic counter and drives the real request using its normal wakeups until a new child is registered. The tests hold the ordered proposal gate throughout this observation and admit no concurrent request. A prior completed CreateCollection/Upload slot cannot satisfy the boundary. There are no sleeps, polling retry loops, or synthetic completion signals.

Both existing tests retain every durable outcome assertion. The added registry regression first leaves an earlier completed slot in the registry, then pauses the new request in actual preflight and proves the observation remains pending. After admitting its child, it cancels the response waiter and proves actual drain stays pending until that child is released and its effect occurs.

Validation performed: rustfmt stdin parsing/formatting of the four proposed files, `git apply --check`, and exact source hash checks. No Rust build or test ran. Proposed commands for the coordinated gate are the new `admission_boundary_ignores_prior_slot_and_pending_preflight_before_retained_child` regression plus the two original failing tests, followed by the already planned full engine coverage.

Adjacent observations, outside this focused patch: the ordered-authority and credential-expiry tests in `service_staged_stop_tests.rs` also use a single outer poll. Their existing final assertions do not establish the claimed actual proposal queue boundary. Proving relative mutex queue order needs a worker-side acknowledgement that its lock future was actually polled, which is a different boundary from registry admission. Also, the current staged read uses a directly awaited blocking handle; this patch does not claim to fix or validate broader blocking-child join ownership.
