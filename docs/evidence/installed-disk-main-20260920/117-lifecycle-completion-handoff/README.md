# Lifecycle completion phase handoff

This target-only one-file proposal follows the exact failed117 binary's static stack evidence in `../117-lifecycle-static-stack/manifest.json` (SHA 4e805b432961a998facf60361f66af4de3d7649f3c8b31db5f5d9b1604dd1f11). No actual source edit, Cargo invocation, binary execution, or test replay was performed here.

The old complete_recovery poll frame uses 1,349,120 bytes and directly enters the 312,256-byte expiry-resolution poll frame, with a 71,600-byte outer fixture frame also live. These prologue sizes establish substantial nested stack pressure; without a captured faulting backtrace they do not identify the exact117 crash instruction. The existing boxed future allocation does not remove the executing poll frame. Root's exact-binary LLDB run passed, so no crash stack was available from it.

The preparation portion now returns CompletionFixture, moving the same actual Fixture, Database Arc, RecoveryStart, attestation keys, completion phase UUID, TargetCompletionFact and signed outcome to the existing outer coordinator. That preparation future and its poll frame finish before the coordinator polls expiry resolution or normal completion resolution. The coordinator then moves the same live fixture/request/keys into the activation, retirement or cleanup continuation. Existing route publication remains another sequential phase after that continuation returns. There is no new task, detached work, request identity, authorization, retry, stack setting, worker count, or deadline.

The actual bodies that prepare the completion, continue activation/retirement/cleanup, and implement all subsequent helper functions are byte-identical to the baseline. All assertion sites, Duration expressions and context-construction sites are preserved. Existing response guards in preparation already have explicit drops or statement/loop scopes; the handoff carries the actual persistent fixture/database and all data needed by later effects. Unneeded owned fixture data from completed setup can retire when that phase returns. The prepared completion fact and signed outcome are constructed in exactly their previous position before the handoff.

This is an evidence-based structural correction, not a claim that the new stack bound is already measured or the lifecycle test has passed. After coordinated application, compile once and statically inspect the new preparation/coordinator/continuation prologues and the absence of a nested prepare-to-expiry poll edge. Then use the unchanged original lifecycle cases with their original deadlines and checks. The normal production memory/ownership qualification remains separate.
