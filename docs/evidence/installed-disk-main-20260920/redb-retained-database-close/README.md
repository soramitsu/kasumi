# Retained database close prerequisite

Target-only, uncompiled, five prepared actual-file backend tests. Requires the exact102-redb-terminal-corrections patch recorded in manifest before application; db.rs baseline contains that package's first-I/O assertion correction. No actual source edits or Cargo runs.

The current consuming Database::close unwinds its actual Database before NodeDatabase can retain it. TransactionalMemory::close also combines shutdown and backend errors with Result::and, losing the second failure. The new inline RetainedDatabase must be installed in external admitted custody before close. It fences database borrows on the first request, permits only transaction-busy retry, calls shutdown and actual backend close separately by borrow, records original results/panic payloads and never replays either entered phase. Backend errors and either panic keep Retained. Successful backend close plus a returned shutdown result permits Settled while original shutdown errors and actual allocation backing remain owned until disposal. No self-retaining census, memory guarantee or production adoption is claimed.

The shared shutdown helper now propagates a newly failing flush instead of discarding it and observing only a later already-fenced settlement error. Existing already-fenced shutdown behavior is preserved. Five proposed tests use actual FileBackend ownership: accepted reader busy then successful close/reopen; original shutdown error with successful backend release; both original errors; shutdown panic with separate backend release; and backend-close panic. Repeated calls assert no new effects and original object identity. Uncertain backends/owners remain in three fixed test-process census slots. Failed/panicked backend release also proves its file lock is still held. Arbitrary panic backing remains unbounded and production caller/census/NodeDatabase/staging adoption remains required.

The old consuming API remains used by existing callers and is not a supported production fallback for the planned admitted writer; complete direct migration is still open. This package is an internal ownership prerequisite, not release completion.
