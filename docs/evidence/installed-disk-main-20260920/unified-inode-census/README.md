## Accounting proof

Let N be max_census_entries and R be the configured root count. The traversal increments work before considering the name, and rejects above N. Each enrolled non-root inode therefore consumes at least one work unit, regardless of whether readdir returns dot entries. A complete fresh census has at most N+R total entries, including configured roots. Its shared map uses that replacement bound.

After installation/reconciliation, existing create_file admission can independently grow the regular-file count to N while retaining the census's directories. Directories are immutable in this draft (no directory creation API). Directory count stays at most N+R, so the retained map has at most 2N+R entries. Using a single N+R cap would silently reduce existing file admission. The patch changes the old map-length quota to the already-maintained regular-file counter to preserve the original policy.

The full fixed reservation is table(2N+R) + table(N+R), where table(X) remains 4*max(X,4)*(size_of(identity,typed_inode)+16)+4096. Existing and replacement ledger allocations remain simultaneously funded, including each original growth allowance. Counts, insertion and mutations remain serialized by NodeDisk state. A failed or cancelled census drops only its unpublished replacement; the installed union and resident lease remain retained. Successful replacement moves the entire union in one assignment. Physical identity collisions are now rejected across kinds in the shared map as well as within each kind.

Do not reuse this proof unchanged after adding directory namespace mutation. Any future directory admission must establish a bounded directory count; approving an unbounded new directory population invalidates 2N+R. No such API or policy is invented here.

Native formula output (native-02/formula.stdout) uses exact proposed memory.rs and ledger.rs, and field declarations extracted from the proposed sources. Validation, external pointed-to implementations and Uuid are explicitly stubbed. It is layout/formula evidence, not a production crate build, exact allocator bound, RSS result or native filesystem qualification. Measured ARM64 layouts: AccountedFile72, AccountedDirectory88, AccountedInode88, FileOwner216, DirectoryOwner72, State152, NodeDisk352 bytes. The enum does not add another maximum map per kind.

For N=1,000,000,4096+4096 handles,depth64,name255 and one actual illustrative root (data,/var/lib/kasumi/data), the old table is960,004,576 and replacement table480,004,576 bytes. ## Concrete migration

- node_disk.rs: one HashMap<Identity,AccountedInode>; separate scalar directory count; snapshot, startup and successful reconciliation consume one union. File count retains its original meaning.
- new ledger.rs: explicit File/Directory variants, typed shared/mutable accessors, common binding and checked retained/replacement cardinalities. No type-erasing fallback, unsafe conversion or allocation in accessors.
- census.rs: roots/directories/files insert into the same physical identity space; parent child-count and directory settlement lookup use typed directory access. Dot-entry work accounting stays unchanged.
- file.rs: all enrolled-file comparisons, settlement, publication and destruction use typed file references; file creation checks state.files. Existing absence/conflict path rules remain scoped to files, preserving the prior file behavior. Strict directory ancestry and namespace accounting adoption are still outstanding below.
- directory.rs: one map for ancestry/binding checks and handle count changes. Directory snapshots no longer retain an independent capacity allocation.
- memory.rs: separate retained/replacement bounds with unchanged checked table/growth estimate and all existing owner/path/cursor workspaces.
- tests.rs: former file-only map-size assertions now assert the file counter; typed file fields remain asserted. Directory failure tests compare the whole retained union. A new real NodeDisk regression prepares a child directory, fills all8 file slots, checks union length10, rejects a ninth file without creation, and verifies failed work-limited recensus retains the old union. This filesystem test is present but UNRUN.
- server persistent_disk.rs and runtime_memory.rs select mandatory directory limits; standalone.md documents that operator policy.
