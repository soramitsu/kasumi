# Canonical allocator encoding into one buffer

Target-only three-file successor to encoded-length patch `055fc2a64f3477a0dc6d6e5a1a086afbf2f5df521ebd863936b60c82bf46a7d3`. It changes bitmap.rs, buddy_allocator.rs and region.rs; page_manager opening ownership and all actual workspace source are untouched by this package. No Cargo or native test has run here.

`BuddyAllocator::encode_into` and `RegionTracker::encode_into` require an exact-length caller-provided mutable slice. They first run the recursive checked length pass from the prerequisite and validate the destination length. Either scalar `AllocatorEncodingError` leaves all bytes unchanged and allocates nothing. No physical I/O is part of these functions. After successful preflight, the immutable borrow preserves all geometry. Nested writers consume successive disjoint output tails and return their written prefix lengths. Their additions, offsets, slices and u32 casts are bounded by the same complete preflight; no late fallible conversion, collection, checksum or allocation is introduced while writing.

The canonical bytes remain identical. Bitmap and buddy metadata store absolute u32 end offsets; tracker metadata stores individual u32 lengths. Buddy padding remains three zero bytes. Bitmap words encode their logical word count only, including the same final-word contents as the original serializer. The original decoder and checksum bodies are unchanged. The manifest pins those bodies and compares normalized original serializer tokens with the test-only reference implementations; only reference-method names and formatting differ.

The production `to_vec` methods retain their existing infallible internal signatures and invalid-internal-state panic boundary. Invalid geometry is now detected before allocating output. Valid geometry allocates one exact-sized zeroed output, invokes the checked buffer encoder, and returns it. The second immutable length pass checks metadata only; it does not serialize twice. The error branch after allocating the exact output is unreachable while that immutable geometry and slice length remain unchanged; it is not a fallback representation. The old nested-vector algorithms exist only under `cfg(test)` as independent exact-byte references. Bitmap/grouped-bitmap allocating helpers also become test-only because production parents directly fill their final output. The new production path has no alternative serializer.

Seven prepared tests cover grouped/recursive bitmap boundaries and resize, every supported buddy order with empty/partial/full and allocated shapes plus resize, and tracker orders/region boundaries through MAX_REGIONS plus resize. Each compares canonical output to the original algorithm, uses guarded caller buffers, requires zero observed allocations during encoding and exactly one allocation in `to_vec`, and rejects empty/short/long buffers without changes. Missing nested backing and order metadata must return `InvalidGeometry` before even the outer header changes. Tests also preserve checksum observations and roundtrip bytes. These tests are prepared, not executed; the existing checksum and fault suites must remain in the parent's original vendor qualification.

This removes nested level/order byte vectors, the tracker length-vector allocation, and tracker child serialization solely to measure lengths. It does not remove the final encoded output or the full decoded prepared allocator copy in `try_save_allocator_state`. Zero-filled allocator-state values, the scalar reservation inventory, decoding allocations, checksum scratch, resident allocator/cache/page ownership, COW path and extraction scratch, debug maps and old/new allocation overlap still need complete admission and bounds. No total workspace, RSS ceiling, protected free-page pool, maintenance extension reserve or at-cap progress claim is made.

Static checks are target-file rustfmt, exact prerequisite/live-base hashes, exact unchanged decoder/checksum bodies, normalized original/reference serializer equality and `git apply --check` on master. They do not qualify runtime behavior.
