# Required opening fault matrix

The eleven proposed tests are an initial implementation check, not this complete qualification. Run after root integration with the original full vendor lib command and supported feature builds. Retain original failed attempts. Do not widen deadlines, remove savepoints/repair, drop uncertain owners, or substitute an in-memory backend for the physical-lock assertions.

1. Cache preparation: before CheckedBackend attachment, reject/force unwind and prove the exact raw Box/backend remains, zero backend calls occurred, and later close returns its original result once. Include geometry refusal and allocation instrumentation. Actual allocation-failure behavior must distinguish catchable unwind from process-aborting OOM; no cleanup report can claim an aborted process returned.
2. Every physical initialization phase: sweep one injected error and one unwind at len/read/resize/write/sync/growth settlement while capturing the exact phase and call ordinal. At each failure prove exact first cause identity, retained raw/cache/memory owner, no implicit close, and no replay. Combine each representative primary failure with successful, erroring and panicking close; preserve the independent original secondary cause and actual file lock when release is unproved.
3. Repair: existing clean allocator load; absent/stale snapshot; unclean valid winning root; invalid winning checksum; explicit repair abort; arbitrary callback unwind at every actual progress callback. Verify supported repair and canonical rejection behavior, full bytes unchanged for rejected obsolete inputs, and retained exact cache/memory throughout callbacks. No repaired root may publish on body failure.
4. Bootstrap begin/body: inject actual read failures while restoring persistent savepoint counter and rows. The exact write object must already be in its retained slot before repaired-root assignment or the first restoration read. Close must separately observe the original body outcome, abort/rollback, disposal and backend close. A panic in abort/disposal must not become successful physical drain.
5. Bootstrap commit: exercise actual prepared-header failure before/after winner write, capacity denial with successful rollback, denial with rollback failure, opaque unwind, and allocator fence. Successful rollback is settlement but must not publish Ready when the original commit failed. An uncertain transaction must remain in a fixed census slot; close must not release its backend or recreate a new transaction.
6. Persistent savepoints: create several savepoints, clean close and retained reopen; prove original IDs, read roots, next-ID advancement and restore semantics across bootstrap abort. Repeat through repair's bootstrap commit. Dispose actual transactions through the exact matching retained witness; wrong-owner and failed-opening witness paths must refuse.
7. Original admission fence: simultaneous original I/O error and actual owner_failed panic (proposed test); concurrent/reentrant callback observation must report Entered without waiting or replay. Hold one panic report while acquiring a second and prove it reports temporarily borrowed; release and compare original payload identity again. Forwarding must use the exact same underlying admission Arc; own failed latch must already reject while inner callback is still running or has panicked.
8. Lifetime: open-success writer/read owners keep close Waiting and preserve actual locked file. Release each actual child and retry observation. No weak/count guess may establish closure. Compare callback/backend/control-block/transaction allocations and error-payload drops against funded leases; every backing allocation must die before its credit returns. The proposed primitive intentionally does not implement those leases.

Integration scope still required: mandatory admitted opening census before backend creation, typed resident/workspace/outcome plans, all twelve commits plus two table-initialization sites, scratch spool borrowed terminal adoption, and original consumers/tests updated together. No optional retained mode is an acceptable production end state.
