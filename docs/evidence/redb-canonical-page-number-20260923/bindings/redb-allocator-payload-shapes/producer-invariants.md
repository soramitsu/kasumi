# Producer invariants used by the borrowed payload checks

These claims concern BuddyAllocator and RegionTracker output in the current source, not arbitrary U64GroupedBitmap or BtreeBitmap values.

BuddyAllocator::new initializes each padded bitmap full. Every clear/set operation addresses a logical page index, and new free ranges are split or merged by free_inner. The representation has at most MAX_MAX_PAGE_ORDER + 1 orders; order k has floor(region_pages / 2^k) logical entries and the height derived from floor(full_region_capacity / 2^k). BtreeBitmap::new_padded and resize derive every parent length by repeated ceil(child_length / 64). A parent bit is the full/not-full state of its corresponding child u64 word.

Generic U64GroupedBitmap::resize shrinking alone leaves its previous word values intact. The buddy producer does more: BuddyAllocator::resize, before shrinking any bitmap length, walks the entire removed page interval and record_alloc_inner marks each removed extent allocated, splitting any crossing free block. Thus entries for blocks straddling or beyond the new end are set before their lengths are reduced. Full initialization plus this explicit removal step preserve full non-logical last-word bits for the canonical buddy producer. The validator must not be generalized to claim this about standalone grouped bitmap resize. The all-order producer test is required runtime evidence for this distinction and must not be weakened to exclude shrinking or retained capacity if it fails.

RegionTracker::new initializes every order bitmap full with padded height for MAX_REGIONS. Its resize only grows logical capacity. Allocators::resize_to shrinking marks every removed region full at every order and retains the tracker length; growing marks only actual new/existing region indices free. Therefore retained capacity can exceed current snapshot regions and must be accepted, while a free marker naming an absent region is invalid. No claim is made that an existing region's optimistic marker precisely equals its buddy allocator's current availability.

Buddy free blocks must be represented at only one order; two same-order free buddies below max_order must be merged. The borrowed validator checks these rules using existing free-bit positions and their ancestors, rather than allocating a page occupancy map. suffix_free uses those nonoverlapping free blocks to cover the discarded interval and handles a shrink boundary in the middle of a larger free block.

Snapshot rows describe the pre-shrink prepared allocator. try_save_allocator_state clones live state, excludes writer-private current-system and eligible DATA frees in that prepared copy, then serializes. TransactionalMemory::commit subsequently shrinks the live layout from actual trailing-free state before publishing and physically truncates after durable winner. All removed pages therefore must also be free in the prepared snapshot. A matching snapshot can safely grow to physical layout after an unclean extension. A stale snapshot's discarded pages need not be free because that snapshot will not be loaded; its complete internal representation is still checked before repair is allowed.
